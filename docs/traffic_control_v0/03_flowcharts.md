## 3. 시나리오 A — 교차 (신호등만으로 해결)

```
robot-1: (80,300) → (600,300)  동쪽으로
robot-2: (340,60) → (340,520)  남쪽으로
                교차점 (340,300)

robot-1              robot-2                        FMS
   │                    │                            │
   │ LeaseRequest       │                            │
   │  캡슐 5개, r=14     │                            │
   ├───────────────────────────────────────────────▶ │ 원장 비어있음
   │◀─── LeaseGrant(PROCEED, held) ────────────────  │ → 승인
   │                    │                            │
   │                    │ LeaseRequest (교차점 포함)  │
   │                    ├──────────────────────────▶ │ robot-1 원장과 겹침!
   │                    │                            │ → 존 tz-1 FORMING
   │◀── BidRequest(tz-1) ──────────────────────────  │
   │                    │◀── BidRequest(tz-1) ─────  │
   ├─ TrafficBid(71.44) ──────────────────────────▶  │
   │                    ├─ TrafficBid(12.09) ──────▶ │ 순서 [1, 2]
   │                    │                            │
   │                    │◀── LeaseGrant(PARTIAL) ──  │ 교차 직전까지만
   │                    │    held = 교차점 앞까지     │
   │                    │                            │
   │ (통과 중)           │ (경계에서 정지, HOLD)      │
   │                    │                            │
   ├─ LeaseRelease(교차점 지난 캡슐) ──────────────▶  │ 원장에서 삭제
   │                    │                            │ → 대기자 재평가
   │                    │◀── LeaseGrant(PROCEED) ──  │ 해제
   │                    │  (재출발)                  │
   │                    │                            │
   │                    │                            │ 다툼 종료
   │◀── ZoneUpdate(LEFT) ──────────────────────────  │ → tz-1 파기
```

**FMS는 맵을 한 번도 보지 않았다.** robot-2 는 "여기까지"라는 회랑만 받았다.

## 4. 시나리오 B — 로봇이 경로를 이탈 (F1 대응 확인)

```
robot-1 이 회랑 안을 주행 중, 갑자기 앞에 사람이 나타남

robot-1                                              FMS
   │                                                  │
   │ (센싱) 경로 위 20 px 앞에 장애물                 │
   │                                                  │
   │ 자기 occupancy 갱신 → replan                     │
   │  → 새 경로는 회랑 안에서 살짝 옆으로 비껴감      │
   │                                                  │
   │ ★ 새 경로가 held 안에 완전히 들어가나?           │
   │                                                  │
   ├── 예 ──▶ 그냥 계속 주행. FMS에 알릴 필요조차 없다 │
   │          (PathUpdate 는 L1 용으로만 보냄)         │
   │                                                  │
   └── 아니오 ──▶ 회랑 경계에서 정지                  │
                  │ LeaseRequest(새 경로용 회랑)      │
                  ├────────────────────────────────▶  │ 재평가
                  │◀── LeaseGrant(...) ─────────────  │
```

**핵심**: 회랑 안에서의 이탈은 FMS와 무관하다. 안전이 깨지지 않는다.
경로 기반 방식이었다면 이 순간 안전 논증이 무너졌다 (`01_design.md` §2.2).

또 하나: **replan 해도 멈추지 않는다.** 경로 기반 방식은 계획이 바뀌면 권한이 무효가 되어
새 권한을 받을 때까지 정지해야 했다. 회랑 방식은 영역만 유지되면 계속 간다.

## 5. 시나리오 C — 정면 (에스컬레이션 E2 → E3)

```
좁은 복도에서 robot-1(서→동), robot-2(동→서)

                                                     FMS
robot-1              robot-2                          │
   │ (복도 절반 확보, 주행 중)                        │
   │                    │ LeaseRequest (복도 반대편)  │
   │                    ├──────────────────────────▶ │ robot-1 원장과 겹침
   │                    │                            │ → tz-2, 시드 [1:88, 2:31]
   │                    │                            │ → L1 조정도표 조회:
   │                    │                            │   반대각 장벽 = 정면
   │                    │                            │   "대기로는 안 풀림"
   │                    │◀── LeaseGrant(STOP) ─────  │
   │                    │                            │
   │                    │◀── EvasionRequest ───────  │ E2
   │                    │    round=r1, REROUTE       │
   │                    │    release_hint = 복도 쪽  │   ★ robot-2 자기 임대의
   │                    │      자기 보유분           │      부분집합일 뿐
   │                    │                            │
   │                    │ release_hint 영역을        │
   │                    │ extraBlocked 에 넣고 A*    │
   │                    │                            │
   │                    ├─ EvasionReply(REROUTE,     │
   │                    │    새 경로 + LeaseRequest)─▶│ 원장과 대조 → 겹침 없음
   │                    │◀── LeaseGrant(PROCEED) ──  │ 채택. 둘 다 정상 주행
   │                    │                            │

── 만약 우회로가 없었다면 ──

   │                    ├─ EvasionReply(NONE) ─────▶ │ E3 로 승격
   │                    │◀── EvasionRequest ───────  │
   │                    │    round=r2, VACATE        │
   │                    │    breadcrumb_hint=[bc-17] │   ★ robot-2 자기 이력
   │                    │                            │
   │                    │ bc-17 로 가는 짧은 대피     │
   │                    │ 회랑 생성 (도달성은 자기가) │
   │                    ├─ EvasionReply(VACATE, ...)▶│ 승인
   │                    │  (복도 입구 홀로 대피)      │
   │                    │                            │
   │ (통과)              │                            │
   ├─ LeaseRelease(복도 전체) ────────────────────▶  │
   │                    │◀── LeaseGrant(PROCEED) ──  │ robot-2 원 목적지로 재계획
```

**FMS는 "복도"라는 단어도, 그 폭도, 옆 홀의 존재도 끝까지 모른다.**

## 6. 에스컬레이션 사다리

낮은 단계부터. 실패해야만 올라간다.

```
                 ┌─────────────────────────────┐
                 │ E0  다툼 없음                │
                 │     → PROCEED               │
                 └──────────┬──────────────────┘
                            │ 원장과 겹침
                            ▼
                 ┌─────────────────────────────┐
                 │ E1  순서 조정 (신호만으로)    │
                 │     선순위 PROCEED           │
                 │     후순위 PARTIAL/STOP      │
                 └──────────┬──────────────────┘
                            │ L1 조정도표: 단조 해 없음
                            │ (= 대기로는 절대 안 풀림)
                            ▼
                 ┌─────────────────────────────┐
                 │ E2  우회 요청                │
                 │     EvasionRequest(REROUTE) │
                 │     → propose–verify        │
                 └──────────┬──────────────────┘
                            │ NONE 회신 or 검증 2회 실패
                            ▼
                 ┌─────────────────────────────┐
                 │ E3  대피 요청                │
                 │     EvasionRequest(VACATE)  │
                 │     + breadcrumb_hint       │
                 └──────────┬──────────────────┘
                            │ NONE 회신
                            ▼
                 ┌─────────────────────────────┐
                 │ E4  순서 반전 후 반대편에     │
                 │     E2/E3 재시도             │
                 │     (MAX_REVERSAL = 1)      │
                 └──────────┬──────────────────┘
                            │ 실패
                            ▼
                 ┌─────────────────────────────┐
                 │ E5  존 전체 동결             │
                 │     전원 STOP + UI 경보      │
                 │     운영자 개입              │
                 └─────────────────────────────┘
```

### propose–verify 루프 (E2/E3 내부)

```
   FMS                                   로봇
    │  EvasionRequest(release_hint, mode)  │
    ├────────────────────────────────────▶ │
    │                                      │ 자기 지도로 대체 회랑 계산
    │  EvasionReply(새 회랑)                │
    │◀──────────────────────────────────── │
    │                                      │
    ├─ 원장과 대조                          │
    │   ├ 겹침 없음 → 승인. 종료            │
    │   └ 겹침 있음 → 그 부분을 새 release_hint 로 삼아 재요청
    │                 (MAX_REROUTE_ROUNDS = 2 회까지)
```

FMS는 지도 없이 **반례만** 만들고, 로봇은 지도로 **후보만** 만든다.
어느 쪽도 상대의 지식을 필요로 하지 않는다.

## 7. 트래픽 존 수명주기

```
     ┌─────────┐   회랑 다툼 발생    ┌──────────┐
     │  없음    │ ─────────────────▶ │ FORMING  │  BidRequest 방송
     └─────────┘                     └────┬─────┘  BID_WINDOW_MS 대기
          ▲                               │
          │ 멤버 0                        │ 시드 수집 완료 (또는 타임아웃)
          │                               ▼
     ┌────┴─────┐   멤버 이탈       ┌──────────┐
     │ DRAINING │ ◀──────────────── │  ACTIVE  │  E0/E1 신호 발급
     └────┬─────┘                   └────┬─────┘
          │                              │ L1: 단조 해 없음
          │ 잔여 멤버 계속 관제           ▼
          │                         ┌──────────┐
          │                         │ EVADING  │  E2/E3 propose–verify
          │                         └────┬─────┘
          │                              │ 채택 or 실패
          └──────────────────────────────┘
```

- **가입** — 새 로봇의 요청이 존 멤버의 원장과 겹치면 즉시. 로봇에게는 `zone_id` 만 통지.
- **탈퇴** — 그 로봇의 회랑이 어떤 멤버와도 안 겹치고, 요청이 전부 PROCEED 이면.
- **파기** — 멤버 1명 이하. 사용자 시나리오 6("남은 대상이 모두 빠져나갈 때까지 FMS 관여")을 보장.
- **합병** — 두 존 사이에 다툼 발생 시 union. **시드는 재추첨하지 않는다** (라이브락 방지).
- **히스테리시스** — 다툼이 사라져도 `ZONE_HYSTERESIS_MS` 동안 멤버십 유지 (요동 방지).
