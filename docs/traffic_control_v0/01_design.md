# 01 — 설계

---

## 1. 문제

`bg_fms` 에서 여러 대의 가상 로봇이 동시에 주행한다.
로봇은 **서로를 감지하지 못한다**. 정적/동적 장애물은 자기 occupancy 로 피하지만,
다른 로봇은 보이지 않는다. 따라서 로봇 간 충돌을 막는 유일한 수단은 FMS의 제어다.

---

## 2. 왜 "경로 기반 권한"이 아니라 "영역 임대"인가

### 2.1 먼저 시도했던 것

FMS가 로봇들의 경로를 모아 조정도표(coordination diagram)를 만들고,
각 로봇에게 **"네 경로 위 s=218까지 가도 된다"** 는 스칼라 하나(`s_limit`)를 내려보내는 방식.
철도 CBTC 의 이동폐색(movement authority)과 같은 구조다.

### 2.2 왜 무너지는가 — F1

이 방식의 안전 논증은 **"로봇이 앞으로 그 경로 위에 있을 것"** 을 전제한다.
자율주행 로봇은 레일 위가 아니므로 그 전제가 성립하지 않는다.

```
로봇이 복도를 지나다 사람을 보고 30 px 옆으로 비켰다.
  → 로봇은 이제 자기가 신고한 경로 밖에 있다
  → s_limit 은 여전히 "218까지 OK" 라고 말하고 있다
  → 실제 몸은 옆 로봇의 예약 튜브 안에 들어가 있을 수 있다
  → 예약끼리는 disjoint 인데, 로봇끼리는 충돌한다
```

**불변조건이 참인데 충돌이 난다.** 논증이 성립하지 않는다.

이건 인용하려던 이론들의 **명시적 가정**이기도 하다.

- Kant & Zucker (1986): VPP 는 **경로가 이미 고정된 뒤** 속도만 정하는 문제
- Siméon·Leroy·Laumond (2002): *"robots moving along **fixed** independent paths"*
- CBTC 이동폐색: **열차는 궤도를 벗어날 수 없다.** 그래서 1차원 스칼라로 충분했다

전부 "경로 이탈 불가"를 깔고 있다. 자율주행 로봇에는 맞지 않는 모델이다.

### 2.3 고친 방식

```
  이전 : "네 경로 위 s=218 까지 가도 된다"        ← 경로 위의 1차원 점
  확정 : "이 영역 R 은 네 것이다. R 밖으로 나가지 마라"  ← 2차원 공간
```

- 로봇은 **R 안에서는 무엇을 해도 된다.** 사람을 피해 비키든, 멈추든, 제자리 회전하든, 뒤로 가든.
- R 밖으로 나가야 하면 **먼저 멈추고 새 임대를 요청**한다.
- R 은 로봇 footprint **전체**를 담아야 한다.

### 2.4 이게 왜 세 가지 사실을 한 번에 닫는가

> **I1 (공간 배타)** 임대된 회랑들은 서로 disjoint 하다.
> **I2 (구속)** 로봇의 몸 전체는 항상 자기 회랑 안에 있다.

따름정리: I1 ∧ I2 ⟹ 두 로봇의 몸은 절대 겹치지 않는다. 증명 한 줄.

| 이전 방식이 의존하던 것 | 확정안 |
|---|---|
| 로봇이 보고한 경로를 실제로 따라간다 (**F1**) | **무관.** 회랑 안이면 뭘 하든 됨 |
| FMS가 아는 pose 가 최신이다 (**F2**) | **무관.** 로봇은 자기 회랑 어딘가에 있음 |
| FMS의 맵이 현실과 일치한다 (**F2**) | **무관.** 배타성은 순수 기하 문제 |
| 로봇 속도·제동 모델이 정확하다 | **무관.** 경계 전에 멈추는 건 로봇 책임 |

### 2.5 신호등 비유가 정확해지는 지점 — F3

| | 이동폐색 (이전) | **고정폐색 / 연동장치 (확정)** |
|---|---|---|
| 전제 | 차량이 궤도 위에 있다 | 차량이 **어디로 튈지 모른다** |
| 관제가 주는 것 | 진행 한계점 (1D) | **구간 점유권 (2D)** |
| 관제의 질문 | "얼마나 더 가도 되나" | **"이 구간 써도 되나" → 진행/정지** |

철도 신호가 고정폐색 → 이동폐색으로 진화한 건 **열차가 레일을 벗어날 수 없기 때문**이다.
로봇은 레일이 없으므로, 오히려 **고정폐색 쪽이 맞는 모델**이다.

같은 구조: 항공 관제의 공역 블록 할당,
그리고 **Buffered Voronoi Cell** (Zhou et al., RA-L 2017) — 각 로봇이 자기 셀 안에서만
계획하면 셀이 disjoint 하므로 충돌이 **구조적으로** 불가능하다는 증명. I1·I2 의 이론적 근거다.

## 3. 역할 분리

```
┌──────────────────── 로봇 (공간의 진실을 아는 유일한 주체) ────────────────────┐
│  · A* 경로 계획 (정적 장애물 + 동적 장애물 + 센싱으로 알아낸 것)            │
│  · 회랑 요청: 어디를, 얼마나 넓게 빌릴지 스스로 결정                        │
│  · 회랑 구속 준수: 몸이 경계를 넘지 않게 스스로 감속/정지                   │
│  · 회랑 반납: 확실히 벗어난 부분만 명시적으로 반납                          │
│  · 회피 요청에 대한 답: 대체 회랑을 자기가 만들어 제출                      │
└──────────────────────────────────────────────────────────────────────────────┘
             ▲ LeaseGrant(초록/노랑/빨강)   │ LeaseRequest / LeaseRelease
             │ EvasionRequest(자기 임대 구간)│ EvasionReply(새 회랑) / Pose / Path
┌──────────────────────── FMS (신호등 / 배타 중재자) ──────────────────────────┐
│  · 임대 원장 관리: 누가 어느 영역을 쥐고 있는가                             │
│  · 요청 승인/거절: 기존 임대와 disjoint 한가 (순수 기하)                    │
│  · 통과 순서 결정: 시드 추첨 + 조정도표 예보                                │
│  · 교착 회피: Banker 안전상태 검사                                          │
│  · 트래픽 존 관리: 다툼이 끝날 때까지 관여                                  │
│  ✗ 좌표를 만들지 않는다. 경로를 만들지 않는다. 대기 지점을 고르지 않는다.   │
└──────────────────────────────────────────────────────────────────────────────┘
```

한 문장: **FMS는 "누가 어디를 쓸지"를 정하고, 로봇은 "그 안에서 어떻게 움직일지"를 정한다.**

## 4. 정보 예산 (하드 룰)

### 4.1 FMS → 로봇, 허용

| 항목 | 왜 안전한가 |
|------|-------------|
| `Signal` (PROCEED/PARTIAL/STOP) | 3값 열거형. 정보량 자체가 없다 |
| `granted` 회랑 | **그 로봇에게 임대된 자기 영역** |
| `lease_until_ms` | 스칼라 |
| `zone_id` | 불투명 문자열. 멤버 목록 없음 |
| `release_hint` | **그 로봇이 쥔 임대의 부분집합.** 자기 영역 |
| `breadcrumb_hint` | **그 로봇 자신의** 통과 이력 id |

### 4.2 FMS → 로봇, 금지

- 다른 로봇의 id, pose, 속도, 목적지, 경로, 회랑
- 존 멤버 수, 자기 등수 (등수도 상대 정보다)
- "왜 거절했는지"의 구체적 기하

로봇 입장에서 세상은 이렇다.
*"관제가 빨간불을 줬다. 왜인지는 모른다. 내 영역 안에서 기다린다."*

### 4.3 P2 완화를 어떻게 쓰는가

FMS가 맵을 봐도 된다. 하지만 **안전 판정에는 넣지 않는다.**

| 용도 | 허용 | 이유 |
|------|------|------|
| UI 렌더링, 운영자 화면 | ✅ | 안전 무관 |
| 회랑 할당 휴리스틱 (병목 막는 임대를 후순위로) | ✅ | 틀려도 처리량 손해뿐 |
| 존·병목 사전 식별, 조기 경보 | ✅ | 확정 판정 아님 |
| 대기 지점·후퇴 지점 지정 | ❌ | **맵에 없는 물건이 거기 있을 수 있다 (F2)** |
| 로봇 대신 경로 생성 | ❌ | 동일. 그리고 F3 |
| 임대 승인/거절의 입력 | ❌ | 판정은 순수 기하(disjoint)여야 한다 |

> **맵은 사전정보(prior)이지 진실(ground truth)이 아니다.**
> 안전 판정에 prior 를 넣는 순간, prior 가 틀렸을 때 안전이 무너진다.

## 5. 안전 논증

### 5.1 주장

각 시점에서 다음이 성립하면 로봇 간 충돌은 발생하지 않는다.

1. **I1** 임대 원장의 모든 회랑이 쌍쌍이 disjoint
2. **I2** 각 로봇의 footprint 가 자기 회랑 안에 포함

### 5.2 증명

로봇 i 의 몸 `B_i ⊆ R_i` (I2), 로봇 j 의 몸 `B_j ⊆ R_j` (I2), `R_i ∩ R_j = ∅` (I1).
따라서 `B_i ∩ B_j = ∅`. ∎

### 5.3 각 불변조건은 누가 지키는가

| | 책임 주체 | 검증 방법 |
|---|---|---|
| **I1** | FMS | 승인 직전 원장 전체와 캡슐 교차 검사 (`05_algorithms.md` §3) |
| **I2** | 로봇 | `applyPose` 에서 회랑 포함 검사 후 이동 (`04_control_flow.md` §2) |

**두 검사 모두 "멍청한 검사"다.** 상위 로직(조정도표, Banker, 추첨)이 전부 틀려도
이 두 검사만 옳으면 충돌은 나지 않는다.

> 똑똑한 로직은 처리량을 위해, 멍청한 검사는 안전을 위해.

### 5.4 논증이 의존하지 않는 것 (중요)

- 로봇이 경로를 따라가는지 — **무관**
- FMS가 pose 를 언제 받았는지 — **무관**
- 맵이 정확한지 — **무관**
- 네트워크 지연 — **무관** (리스 만료 시 정지하므로)
- 조정도표 / Banker / 추첨이 옳은지 — **무관** (처리량에만 영향)

### 5.5 논증이 의존하는 것 (새 신뢰 경계)

- **로봇이 회랑 밖으로 나가지 않는다.**

이게 유일한 로봇 측 신뢰 가정이다.
"경로를 정확히 따른다"보다 **훨씬 지키기 쉬운 약속**이다 — 경계까지의 거리만 보고 멈추면 된다.
그래도 구현 버그는 있을 수 있으므로, FMS가 pose 로 **감시**한다 (`06_safety_and_failures.md` §3).
감시는 안전 논증의 일부가 아니라 **버그 검출기**다.

## 6. 4계층

| 계층 | 역할 | 실패 시 | 문서 |
|------|------|---------|------|
| **L0 안전** | 회랑 disjoint + 구속 | **충돌** | 본 문서 §5, `05_algorithms.md` §2–3 |
| **L1 효율** | 조정도표로 통과 순서를 미리 결정 → 급정거 방지 | 불필요한 정지 | `05_algorithms.md` §4 |
| **L2 생존성** | Banker 교착 회피, 시드 추첨, 에이징 | 멈춤·기아 | `05_algorithms.md` §5–6 |
| **L3 에스컬레이션** | propose–verify 로 대체 회랑 확보 | 멈춤 | `03_flowcharts.md` §5 |

### L1이 왜 여전히 필요한가

경로는 F1에 의해 **약속이 아니라 예보**다. 예보로 안전을 논증할 수는 없다.
하지만 예보로 **미리 순서를 정해두면**, 로봇이 교차로 앞에서 갑자기 빨간불을 받고
급정거하는 대신 미리 감속할 수 있다. 즉 L1은 **승차감과 처리량**의 계층이다.

정면 충돌 검출(조정도표의 반대각 장벽 → 단조 해 없음)도 L1에 남는다.
확정 판정이 아니라 **조기 경보**로 읽는다. 예보가 맞으면 이득이고, 틀리면 헛수고일 뿐이다.

## 7. capability query — FMS가 못 고르면 물어본다

FMS는 좌표를 만들 수 없다(F2, F3). 그래서 고르는 대신 **묻는다**.

```
FMS  : "네가 쥔 임대 중 이 부분을 반납할 수 있나? 대체 회랑을 내라."   ← 자기 영역만 언급
로봇 : "가능. 이 회랑이다."   또는   "불가능."                        ← 유일한 공간 판단자
FMS  : 원장과 대조 → 승인 / 반례와 함께 재요청
```

이 패턴은 이 레포에 이미 있다. 동적 장애물의 `place_query` / `place_reply` 가 같은 모양이다.
FMS가 후보를 던지고 로봇이 자기 기하로 가부만 답한다. **검증된 패턴의 확장**이다.

### breadcrumb

E3(대피)에서 FMS가 후보를 제시하면 빠르다. 그런데 좌표를 만들 수 없다.

해법: **로봇이 지나온 지점은 통과 가능함이 실증된 지점이다.**
로봇이 주행하며 남긴 breadcrumb 을 FMS가 `{id: (x,y)}` 카탈로그로 보관하고,
E3에서 좌표 대신 **id 를 지목**한다. 로봇은 그 id 로 대피 회랑을 만든다.

FMS가 다루는 건 **추정한 지도가 아니라 실증된 점 집합**이다.
통과 이력으로 free space 를 역추정하는 방법도 있지만, 그건 F2의 책임 경계를 흐리므로 기각했다.
추정이 틀리면 FMS가 벽에 로봇을 세우고, 그 순간 안전 논증이 무너진다.

단, breadcrumb 도 **제안일 뿐 지시가 아니다.** 최종 판정은 언제나 로봇이 한다
(그 사이 물건이 놓였을 수 있고, 그건 FMS가 모른다). 자기 breadcrumb 만 쓰므로 P1도 무관하다.

원래 제안했던 시나리오 1~6이 어디로 갔는지.

| # | 원안 | 확정안에서의 위치 | 변경 사유 |
|---|------|-------------------|-----------|

| 3 | 최고 시드 1대는 계속 주행 | 시드 순으로 회랑 승인 (PROCEED) | 단, I1이 우선. 물리적으로 막히면 승자도 STOP |
| 4 | 나머지에게 우회 경로 생성 요청 | **E2** `EvasionRequest(REROUTE)` | 대기로 풀리는 상황이면 요청하지 않는다 |
| 5 | 우회로 + 시드 반환, 재겹침 처리 | **E2~E4** propose–verify 루프 | 시드는 존 단위 sticky. 재추첨 없음 (라이브락 방지) |
| 6 | 존 탈출을 FMS가 끝까지 관여 | 존 상태기계 + Banker | 교착 회피가 "끝까지 관여"의 알맹이 |

`avoidanceMode` 플래그(기본 ON)도 그대로 유지한다 (`07_implementation.md` §1).

## 9. 남는 한계 (정직하게)

- **처리량이 경로 기반 방식보다 낮다.** 영역을 통째로 배타 점유하므로 좁은 통로에서 보수적이다.
  로봇이 회랑 반경을 상황에 맞게 좁게 요청하는 것으로 일부 완화한다.
- **FMS 단일 장애점.** 리스로 안전은 확보되지만 가용성은 아니다.
- **로봇 상호 감지 계층이 없다.** 현재 가상 로봇은 서로를 보지 못하므로 임대 체계가 단일 방어선이다.
  실물에서는 독립적인 지역 근접 정지(ISO 3691-4 계열)를 반드시 별도 계층으로 두어야 한다.
  근접 정지는 "뭔가 가깝다"만 알면 되므로 P1을 위반하지 않는다.
- **n-body 최적성 없음.** 쌍별 조정도표 + Banker 는 근사다. 로봇 2~5대 규모에서는 실용상 문제없다.
