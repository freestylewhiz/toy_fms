# 06 — 안전과 실패 모드

전제: **로봇은 서로를 감지하지 못한다.** 임대 체계가 유일한 충돌 방어선이다.

---

## 1. 충돌이 나려면 무엇이 성립해야 하는가

```
로봇 간 충돌
 ├─ (A) 겹치는 회랑이 임대되었다              → I1 위반
 │       ├─ A1 기하 계산이 틀렸다
 │       ├─ A2 원장이 낡았다 / desync
 │       └─ A3 원장에 없는 점유가 있다
 ├─ (B) 로봇이 자기 회랑을 벗어났다            → I2 위반
 │       ├─ B1 구속 검사 버그 / 오버슛
 │       └─ B2 권한 없이 움직였다
 └─ (C) 로봇이 아닌 것과의 충돌
         └─ FMS는 원리상 모른다 (F2). 트래픽 제어의 범위 밖
```

이 트리가 전수다. 각 가지의 대응이 아래다.

---

## 2. A — 겹치는 임대

### A1. 기하 계산 오류

| 원인 | 대응 |
|------|------|
| 캡슐 근사가 실제 경로보다 좁음 | 근사 오차 `tol` 을 반경에 흡수 (`05_algorithms.md` §1.2). **회랑은 크게 잡는 쪽이 안전** |
| 부동소수 경계 오차 | `CORRIDOR_GAP_PX = 4` 여유. 로봇 이동량(0.6 px/tick)의 6배 |
| `segSegDistance` 구현 버그 | 단위 테스트로 고정. 평행/교차/끝점 케이스 전부 |
| spatial hash 인덱스 누락 | **§2.3 전수 검사가 잡는다.** 인덱스는 가속용일 뿐 판정용이 아님 |

### A2. 원장 desync

FMS와 로봇이 서로 다른 `held` 를 믿으면 위험하다.

- **`LeaseGrant.held` 는 델타가 아니라 스냅샷이다.** 로봇은 덮어쓰기만 하면 되므로
  병합 버그가 원천적으로 없다.
- **반납 교차검증**: `freed ∪ retained == held` 를 FMS가 확인한다 (PI4).
  다르면 반납을 무시하고 경보 → desync 조기 검출.
- `request_id` 매칭으로 늦게 온 옛 응답을 버린다.

### A3. 원장에 없는 점유

**연결이 끊긴 로봇**이 이 경우다. 로봇은 실제로 계속 움직이고 있을 수 있는데
FMS는 모른다. F2의 극단적 형태다.

```
연결 끊김 감지
  → 마지막 pose 를 중심으로 DISCONNECT_HALO_PX = 60 (= 5초 주행거리) 반경을
    영구 점유로 원장에 등록
  → 5초 안에 갈 수 있는 최대 범위를 통째로 막는다
  → DISCONNECT_FREEZE_MS = 3000 이 지나도 복귀 없으면 전 차량 정지 + 운영자 개입
```

halo 를 시간에 따라 키우는 게 이론적으로 맞지만, 곧 맵 전체가 막히므로
3초 후 전면 정지로 전환한다. **가용성을 포기하고 안전을 택하는 지점**이다.

`idle` / 계획 실패 / `plan_blocked` 상태의 로봇은 정상적으로 임대를 쥐고 있으므로
별도 처리가 필요 없다. **임대 보유 자체가 "저기 뭔가 있다"를 표현한다.**

---

## 3. B — 로봇이 회랑을 벗어남

### B1. 구속 검사 버그 / 오버슛

I2는 로봇이 지킨다. 이게 새로운 신뢰 경계다 (`01_design.md` §5.5).

- 한 tick 이동량 0.6 px. `CORRIDOR_GAP_PX = 4` 가 여유를 준다.
- `poseInsideLease` 는 **footprint 전체**를 검사한다. 중심점만 보면 몸이 삐져나간다.
- 이동 전에 검사하고 실패하면 이동하지 않는다 (`tryMove` 체인).

**FMS 측 감시** (안전 논증의 일부가 아니라 **버그 검출기**):

```
pose 수신 시:
  if (footprint(pose) ⊄ held + WATCHDOG_TOLERANCE_PX)
      metrics.violation++
      전 차량 STOP + UI 경보
      회복은 수동
```

`WATCHDOG_TOLERANCE_PX = 2`. pose 가 과거라서 약간의 오차가 있을 수 있으므로 여유를 둔다.
감시가 발동했다는 건 로봇 구현에 버그가 있다는 뜻이고, 그건 수동 개입 사안이다.

### B2. `avoidanceMode = false`

이 플래그가 켜진 로봇은 정확히 "권한을 지키지 않는 이동체"다.

FMS의 대응: 그 로봇의 **전체 경로**(5초분이 아니라 전 구간)를 보수적으로 점유로 등록하고,
다른 로봇들이 그 영역을 못 쓰게 한다.

즉 `avoidanceMode = false` 는 그 로봇에게 자유를 주는 대신
**나머지 전체의 처리량을 깎는다.** 의도한 트레이드오프이고 UI에 명시해야 한다.

경로가 예보일 뿐이므로(F1) 이 보호도 완벽하지 않다. **디버깅 전용 플래그**이며
실운영에서 켜면 안 된다는 걸 문서와 UI 양쪽에 적는다.

---

## 4. C — 로봇이 아닌 것

사람, 다른 업체 장비, 넘어진 팔레트. **FMS는 원리적으로 모른다 (F2).**

- 로봇은 자기 센서/occupancy 로 알고 있으므로 스스로 멈추거나 replan 한다.
  회랑 안이면 FMS 개입 없이 계속 가고, 밖으로 나가야 하면 hold 후 재요청한다.
  → **이 경로는 이미 커버된다.**
- 로봇도 못 보는 경우(사각지대, 갑자기 튀어나옴)는 트래픽 제어의 문제가 아니다.

### 별도로 필요한 계층

```
지역 근접 정지 (현재 시뮬레이터 미구현)
  · 로봇이 자기 센서로 "뭔가 X px 이내에 있다"만 판정하고 즉시 정지
  · 다른 로봇의 경로/id/속도를 알 필요 없음   → P1 위반 아님
  · FMS를 거치지 않음                        → P2 무관, 지연 무관
  · 실물 규격: ISO 3691-4, ANSI/ITSDF B56.5
```

트래픽 제어와 지역 근접 정지는 **직교하는 두 계층**이어야 한다.
어느 하나가 완벽해도 다른 하나를 빼면 안 된다.

현재 가상 로봇은 서로를 감지하지 못하므로 이 계층이 비어 있다.
**v0에서는 임대 체계가 단일 방어선**이라는 걸 명시적으로 감수한다.

## 5. 가용성 실패

| 상황 | 결과 | 근거 |
|------|------|------|
| FMS 프로세스 크래시 | `LEASE_MS = 400 ms` 내 전 차량 정지 | 리스 만료 (PI5) |
| gRPC 스트림 단절 (1대) | 그 로봇 정지 + 나머지는 §A3 halo 처리 | 리스 + halo |
| 네트워크 지연 스파이크 | 리스 만료 → 정지 → 회복 시 재출발 | 안전하지만 덜컹거림 |
| FMS 과부하 (10 Hz 못 지킴) | 리스 만료 → 전원 정지 | 처리량은 죽어도 안전은 유지 |
| L1 조정도표 예산 초과 | **L1을 건너뛴다** | 효율 계층이므로 스킵해도 안전 |
| 클럭 스큐 | 없음 | 리스를 duration 으로 전송 (`02_protocol.md` §4.3) |

전부 **안전 측 실패(fail-safe)** 로 떨어진다. 리스를 넣은 유일한 이유다.

## 6. 라이브락 / 처리량 실패

| 상황 | 대응 |
|------|------|
| 서로 양보하다 둘 다 못 감 | 시드 sticky (`05_algorithms.md` §6.2) |
| 낮은 시드 로봇의 기아 | 에이징 (`05_algorithms.md` §6.3) |
| 존이 매 tick 붙었다 떨어짐 | `ZONE_HYSTERESIS_MS = 500` |
| E2 재요청 무한 루프 | `MAX_REROUTE_ROUNDS = 2` → E3 |
| 의미 없는 찔끔 전진 반복 | `PROGRESS_EPSILON_PX = 2` 미만이면 STOP |
| 도달 불가 영역을 점유해 남을 막음 | PARTIAL 은 앞에서부터만 자른다 (`05_algorithms.md` §3의 `break`) |
| Banker 과보수적 | 로봇 수가 적으면 무시 가능 |
| 회랑을 너무 넓게 요청해 계속 거절 | 로봇이 거절 횟수에 따라 반경을 줄여 재요청 |

## 7. 관측 지표

```
traffic.violation_count          // ★ 0 이어야 한다. 하나라도 나면 심각
traffic.min_pair_distance_px     // ★ 0 아래로 내려가면 충돌. 회귀 테스트의 핵심
traffic.watchdog_trips           // 로봇 구속 위반 감지 (I2 버그)
traffic.desync_count             // freed∪retained != held
traffic.lease_lost_count         // 네트워크/FMS 건강도
traffic.hold_ms_p95              // 처리량 지표
traffic.signal_histogram         // PROCEED / PARTIAL / STOP 분포
traffic.escalation_histogram     // E0..E5 분포. E2 이상이 잦으면 맵/경로 설계 문제
traffic.reroute_success_rate
traffic.zone_lifetime_p95
traffic.ledger_check_ms_p95      // 100ms 예산 대비
traffic.corridor_radius_p50      // 로봇들이 얼마나 넓게 빌리는지
```

`min_pair_distance_px` 가 사실상의 안전 회귀 테스트다.
**모든 통합 테스트에서 이 값이 0보다 큰지 단정한다.**

## 8. 안전 논증 재확인 (체크리스트)

구현 리뷰 시 이 목록을 통과해야 한다.

- [ ] `commitGrant` 가 spatial hash 없이 원장 **전수** 검사를 하는가
- [ ] `poseInsideLease` 가 중심점이 아니라 **footprint 전체**를 검사하는가
- [ ] 리스 만료 시 로봇이 **어떤 이동도** 하지 않는가 (회전 포함)
- [ ] `LeaseGrant.held` 가 델타가 아니라 **스냅샷**인가
- [ ] 반납이 pose 추론이 아니라 **로봇의 명시적 메시지**인가
- [ ] 교통 제어 코드가 occupancy / obstacle 자료구조를 **import 하지 않는가**
- [ ] 로봇에게 보내는 어떤 필드에도 **다른 로봇에서 유래한 기하가 없는가**
- [ ] PARTIAL 이 **앞에서부터만** 자르는가 (뒤쪽 고립 점유 금지)
- [ ] 캡슐 근사 오차가 반경에 **더해지는** 방향인가 (빼는 방향이면 I2 위반)
