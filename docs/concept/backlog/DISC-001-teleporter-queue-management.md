# DISC-001 — 텔레포터 대기열 관리

분류: DISC(심층 논의). 카드: PILOT-17 / fms/planning / To Do.
상태: 후속 논의, 물리적 줄서기 미구현. 논리 FIFO와 접근 중 대기는 기본 구현에 반영했다.

## 합의된 초기 정책

고정 waiting_pose 없이 접근 중 대기 + 논리적 이용 순서 관리 + 도착 후 자동 이탈.
입구 폴리곤 진입 권한이 없으면 영역 밖에서 다른 로봇·장애물을 고려해 정지한다.
로봇 몸체가 출구 폴리곤을 완전히 벗어나면 점유를 해제하고 이탈 지점 도착 시 명령을 완료한다.
기본 대기·허가 동작은 PILOT-16, 맵 전환·자동 이탈 실행은 PILOT-15에서 구현했다.
접근 요청은 durable FIFO로 관리하며, 연결·운영·control epoch가 유효한 요청만 승격한다. 취소와 오프라인 요청은 순서를 보존하면서 승격 대상에서 제외한다.
물리적 대기 구역·슬롯·줄서기 배치는 아직 확정하거나 구현하지 않았다.

## 심층 논의가 필요한 이유

논리적 순서만으로 실제 로봇이 한 줄로 정렬하거나 출구 통로가 비워지는 것은 아니다.
여러 로봇에 같은 대기 좌표를 주면 충돌·교착이 생길 수 있다.
공간 배정과 이용 권한을 분리해서 설계해야 한다.

## 검토 시나리오

- 넓은 홀의 다방향 접근과 좁은 입구의 정면 접근.
- 양쪽 층에서 동시에 몰리는 수요와 한쪽 방향의 지속적인 우선권.
- 순서상 선두 로봇이 접근 불가·오프라인·운영 제외 상태인 경우.
- 대기 로봇이 도착 로봇의 자동 이탈 경로를 막는 경우.
- 예약 취소, 재접속, 서버 재시작과 대기 순서 복원.
- 대기 공간 밖으로 밀려난 로봇의 재진입과 순서 유지.
- 인접한 여러 텔레포터 또는 일반 주행과 대기열이 간섭하는 경우.

## 비교할 대안

| 대안 | 기대 효과 | 추가로 정해야 할 사항 |
| --- | --- | --- |
| 자율 접근·정지 + 논리 순서 | 별도 배치 부담이 작음 | 정체·진입 방해·순서상 선두의 접근 불가 |
| 대기 구역 | 대기 공간을 운용자가 지정 | 로봇별 위치·간격·수용 용량 |
| 대기 경로 | 물리적인 줄의 방향을 지정 | 합류·추월·후진·이탈 통로 |
| 고정/동적 슬롯 | 위치 배정과 순서를 명시 | 크기별 적합성·예약·재배치·편집 부담 |

## 결정할 질문

- 방향별 공정성과 대기 시간 상한을 어떻게 보장할 것인가?
- 이용 순서와 실제 배치 순서가 다를 때 누구를 먼저 이동시킬 것인가?
- 선두를 건너뛰는 조건과 순서 복귀 규칙은 무엇인가?
- 출구 이탈 공간을 어느 범위까지 확보할 것인가?
- 영역별 수용 한도, 우선순위, 취소 및 운영자 개입은 필요한가?
- 교착 검출·해소와 센서 관측·통신 단절을 어떻게 결합할 것인가?
- 처리량·최대 대기 시간·기아·교착·최소 간격 중 어떤 지표로 평가할 것인가?

## 논의 산출물

채택 대안, 적용 조건, 미채택 사유, 기본 정책과의 경계, UI 설정 부담, 검증 시나리오를 기록한다.
