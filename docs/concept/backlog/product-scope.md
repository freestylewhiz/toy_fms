# 통합 확장 범위

상태: 논의 후보. 이번 정리에서 구현을 승인하거나 todo로 등록하지 않았다.

## 멀티맵과 그래프 운영

현재 yard와 large_lab을 별도 FMS 프로세스로 편집·주행에 사용한다. 통합 멀티맵 운영은 미구현이다. 다음 단계에서 실제로 운영할 맵 수, 맵 이동,
좌표계·버전, 기존 리소스 마이그레이션을 먼저 합의해야 한다.
노드/엣지 편집을 그래프 주문 실행과 동일하게 취급하지 않는다.
상세: [FMS 범위](../../fms/backlog/maps-and-graph.md).

## 운영 복구와 책임 범위

수동 해제 후 물리적으로 남아 있는 로봇의 처리, 운영자 인증, 명령·감사 이력 보존 범위를 정한다.
현재 운영 제외는 물리 정지 보증이 아니다.
상세: [운영 정책 논의](../../fms/backlog/operations.md).

## 주행 방식과 이기종 연동

자유 주행·그래프 주행의 적용 단위, FMS/로봇의 계획 책임, 실기 어댑터의 목표를 정한다.
VDA 표준 버전과 지원 기능은 실제 적용 대상이 정해진 뒤 공식 사양을 확인한다.
상세: [로봇 연동](../../robot/backlog/integration.md), [트래픽 확장](../../fms/backlog/traffic-evolution.md).

관련 Backlog 논의 카드: PILOT-8(멀티맵·그래프), PILOT-9(운영 복구·감사), PILOT-10(주행 능력·어댑터).
이 세 카드의 논의가 끝나기 전에는 구현 범위·일정을 확정하지 않는다.
