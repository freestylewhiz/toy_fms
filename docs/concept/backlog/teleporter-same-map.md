# 동일 맵 텔레포터 검토

2026-09-17 사용자 요청에 따른 검토. 구현은 아직 승인하거나 적용하지 않았다.

## 결론

동일 층의 서로 떨어진 두 위치도 하나의 양방향 텔레포터로 연결할 수 있다.
기존 `endpoints` 두 개와 고유 끝점 ID를 그대로 유지하고 같은 `mapId`를 허용하는 방향이 적합하다.
새 리소스 타입이나 별도의 단방향 리소스 두 개는 필요하지 않다.

## 현재 막혀 있는 이유와 필요한 변경

| 영역 | 현재 전제 | 필요한 변경 |
| --- | --- | --- |
| 공통 검증 | 두 끝점은 서로 다른 맵이어야 함 | 같은 맵 허용, 서로 다른 끝점 ID 유지 |
| 배치 화면 | 연결할 층에서 현재 맵 제외 | 현재 층 선택 허용, 화면 전환 없이 두 번째 끝점 배치 |
| 선택·편집 | 현재 맵으로 끝점을 하나 찾음 | 클릭한 끝점 ID로 편집·주행 방향 식별 |
| 진입 허가 | 반대 맵의 준비 상태 확인 | 같은 맵의 두 영역과 출구 경로 확인 |
| 로봇 전환 | 대상 서버를 바꾸고 재접속해 제어 동기화 | 같은 서버에서도 새 제어 세대로 동기화하는 명시적 경로 필요 |
| 점유 해제 | 현재 맵에 있는 끝점을 찾음 | `toEndpointId`로 도착 영역을 정확히 선택 |

특히 `GrpcClient.switchTarget()`은 주소가 같으면 즉시 반환한다. 검증 조건만 풀면
도착 후 제어 동기화를 기다리며 멈출 수 있다. 서버 변경과 무관한 이전 절차가 필요하다.
같은 맵에서는 이미지·점유 격자를 다시 읽을 필요가 없지만 이전 경로·피어 예측·허가는 정리해야 한다.

## 제안 정책

- 기존처럼 명시적 텔레포터 명령에만 반응한다.
- 입구 헤딩 정렬 → 출구 위치·헤딩 적용 → 자동 이탈을 유지한다.
- 두 끝점의 점유 폴리곤이 겹치는 배치는 초기에는 거부하는 안을 권장한다.
- 양방향 한 대 이용권, FIFO, 출구 차단 대기, 연결 단절 시 점유 보존 정책을 유지한다.
- 전역 로봇 ID와 소유 맵은 유지하되 이전 ID·제어 세대를 갱신해 이전 보고를 무효화한다.

## 구현 전에 합의할 사항

겹치는 영역의 허용 여부, 끝점별 화면 이름·선택 방법, 같은 서버의 제어 재동기화 방식을 확정한다.
구현 범위 승인 후 카드와 완료 기준을 정한다. Yard 양방향 이동, 두 로봇 대기, 출구 차단,
전환 중 재접속, 도착 영역의 정확한 점유 해제 및 기존 층간 이동 회귀를 검증해야 한다.
