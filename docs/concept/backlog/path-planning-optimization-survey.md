# 대형 가중 맵 패스 플래닝 최적화 — 1차 조사

관련 카드: [PLAN-17](http://192.168.0.172:3456/tasks/43) · 원인 진단: [ROBOT-6](http://192.168.0.172:3456/tasks/33).

기준일: 2026-09-22. **최신 결정: 축소 격자 방안만 ROBOT-9로 구현 승인. 마지막 추가 합의 절을 우선한다.**

아래 1차 조사 당시 사용자 요청은 접근 가능한 알고리즘·튜닝 기법의 개략 조사와 PLAN 카드 등록이다.
상세 검토·실험은 이후 서브에이전트 조사 취합으로 진행할 예정이다. 이번에는 서브에이전트를
기동하지 않았고, 알고리즘 도입·코드 수정·운영 변경·새 성능 실험을 수행하지 않았다.
아래 우선순위·튜닝 수치는 프로젝트 적합성에 대한 1차 제안이며 확정 설계/완료 기준이 아니다.

## 1. 프로젝트 조건과 조사 초점

- Large Lab: 10000×10000, 1억 cell, 5cm/cell. 정적 occupancy/inflated와 편집 가능한 존·장애물을 사용한다.
- 현재 원해상도 8방향 A*, 큰 맵은 sparse Map, 별도 Bun 계획 프로세스/IPC. 웹·FMS·로봇 계약은 유지한다.
- prefer/avoid는 몸체 여유와 경계 거리 기반 연속 비용, 겹치면 곱하고 상하한을 적용한다.
  forbidden/blocked는 하드 제약이며 prefer를 corridor 정원/점유로 바꾸지 않는다.
- 현재 가상 로봇은 제자리 회전이 가능하고 몸체는 직사각형이다. 실기 운동학은 별도 확정이 필요하다.
- FMS는 교통·점유를 조율하고 로봇은 자유 주행 경로를 계획한다. 그래프 편집 UI가 있다고
  현재 자유 주행을 그래프 전용 주행으로 전환한 것으로 취급하지 않는다.
- ROBOT-6의 고정 장면 진단에서 softCostAt 하위 호출 포함 비용이 planRoute의 약 59%였다.
  실제 교차의 약 75초 지연 중 약 65초는 폐기된 계획 요청에 쓰였다. 두 수치는 서로 다른 측정이다.
  이번 중심은 1회 계획의 비용/탐색량 최적화이며, 반복 폐기 정책은 연계 검토로 분리한다.

근거: [Large Lab](../current/large-test-map.md), [주행](../../robot/current/navigation.md),
[트래픽](../../fms/current/traffic.md), [프로파일·실제 기록](../../robot/backlog/prefer-crossing-diagnosis.md).

## 2. 접근 가능한 알고리즘 후보

효과는 문헌의 일반 성질이며 이 프로젝트에서의 속도 개선은 아직 측정하지 않았다.
구현 복잡도는 기존 TypeScript/Bun 코드 대비 상대 평가다.

HPA* 추상 그래프와 NavMesh는 자동 생성된 자유 주행의 내부 표현 후보다.
운영자가 지정하는 노드/엣지 주행 모드를 자동으로 승인한 것이 아니다.
Nav2/OMPL/Recast는 알고리즘·구현 참고 자료이며 ROS 도입·외부 라이브러리 설치·언어 이전 결정이 아니다.

### 동적 교차와의 연계 후보 — 위 계산 최적화와 별도

- **SIPP 계열**: 위치와 통과 가능한 시간 구간을 함께 계획한다. 움직이는 장애물을 정적으로
  취급하고 계속 재계획하는 문제와 직접 연관된다. 예측 궤적/시각 오차·정지·재개 및 가중
  공간 비용을 넣으면 원 논문의 가정·목적함수를 다시 검토해야 한다. [S10]
- **ORCA 계열의 국소 회피**: 전역 경로와 별도로 가까운 상대와의 속도를 조절하는 후보다.
  전역 A*나 FMS 점유 정책의 대체가 아니며 직사각형 몸체·제자리 회전/속도 제약·정체에 대한
  적용성을 별도 확인한다. 알고리즘의 단순 운동 모델 보장을 그대로 실기에 전이하지 않는다. [S11]

## 3. 알고리즘 교체 전에 비교할 튜닝 기법

아래는 현행 코드와 문헌을 결합한 프로젝트 제안이다. 특히 캐시 구조와 수치 범위는 연구 결과가 아닌 실험 후보다.

| 기법 | 적용 제안 | 조정값·검증 포인트 |
| --- | --- | --- |
| T1 셀/타일 비용 캐시 | 최초 방문 시 존 비용 계산, 같은 셀은 재사용. map/존 revision과 footprint 정책을 키로 사용 | 타일 64/128/256 cell, LRU 예산 예: 16/64MiB를 비교. 128² Float32 비용만 64KiB이며 valid bit/키/인덱스 등 추가 메모리 포함해서 제한 |
| T2 존 공간 인덱스·기하 전처리 | 타일→겹치는 존 목록, 폴리곤 edge 벡터/길이 전처리, 거리·내부 판정 중복 감소 | 폴리곤 오목/경계/겹침 검증. 존 변경 시 경계 여유·avoid 바깥 완충 범위까지 무효화. hard/soft 의미를 동일하게 유지 |
| T3 필요 영역 비용장·거리장 | 전맵 대신 존 영향 영역/활성 타일의 비용장을 생성. 동일 geometry에 factor만 바뀌면 거리장을 재사용하는 안 | 정확한 경계 거리 또는 근사 distance transform 선택. 격자 오차가 몸체/금지·중앙 선호를 깨지 않는지 검수. 근사 방식은 동일 정책 구현이라고 단정하지 않음 |
| T4 비용 양자화 | Float32 연속 비용 대신 정수 등급/구간별 비용을 비교 | 16/64/256단계 등은 후보. factor 곱·상하한·prefer 중앙/avoid 가장자리의 차이 보존 오차를 측정. JPSW 효과를 위해 정책을 몰래 바꾸지 않음 |
| T5 휴리스틱 강화 | 8방향 grid에서는 octile×유효 최소비용 하한을 Euclidean 기준선과 비교. 반복 질의에는 landmark(ALT) 또는 목표 기반 역방향 거리장 후보 | prefer가 1보다 싸므로 무조건 거리×1을 하한으로 쓰면 안 됨. 다중 prefer 겹침의 하한 반영. 비용 감소/목표/맵 변경 시 캐시 하한 재검증 [S12][S13] |
| T6 탐색 범위의 단계적 확대 | 시작~목표 주변 또는 거친 경로 주변 띠에서 먼저 탐색 후 확장 | 큰 장애물 우회 실패를 전역 no-route로 오판하지 않도록 fallback. bbox/띠 한정 결과는 원래 전역 최적해 보장과 구분 |
| T7 open queue·메모리 | stale heap entry 건너뛰기, 동일 f의 tie-break, 타일별 typed array·generation stamp 재사용을 비교 | 더 나은 g값으로 재오픈해야 하는 경우 보존. 전체 1억 셀 배열 초기화로 되돌리지 않음. 확장 수/중복 pop/GC/RSS 측정 |
| T8 선분 비용·단순화 캐시 | stringPull/lineCost의 반복 비용을 캐시하거나 prefix 비용으로 줄이고 smoothing 예산 분리 | 현행 선분 샘플/분할 비용의 동일성부터 확인. 캐시 사용 전 revision 일치·몸체·hard zone 검사. budget 초과 시 검증된 원 경로 유지 |
| T9 정적/준정적/동적 레이어 분리 | 지도·존 비용 캐시는 보존하고 peer 업데이트는 동적 레이어만 변경 | 매 peer 갱신으로 전체 캐시를 날리지 않음. 정적 캐시 보존이 최신 peer 충돌 검사를 생략한다는 뜻은 아님 |
| T10 예산·재사용·통합 구조 | worker 유지·입력 delta·재계산 병합·제한시간 내 검증된 결과를 비교 | 먼저 IPC/큐/탐색/후처리/검증 시간을 분리 측정. C++/Rust/WASM 또는 worker 증가가 먼저라는 근거 없음. 현재 pendingPlan 정지·stale 결과 검사와 함께 검수 |

Weighted A*의 w는 탐색 순서/품질 허용치다. prefer factor와 cost_travel_multiplier 같은
비용 정책 계수를 단순히 변경해 계산을 줄이면 주행 정책이 달라질 수 있다. 별도 승인할 항목이다.

## 4. 1차 권고 순서

1. **동일 정책을 유지하는 기존 A* 개선**: T1/T2/T7/T8로 실제 59% 기하 비용과 중복 작업을 줄일 여지 확인.
2. **탐색량 축소**: 다중 해상도 A*·HPA*를 비교하고, 품질 오차를 허용할 경우 Weighted A*/ARA*를 추가.
3. **변경량 기반 재계획**: LPA*/D* Lite의 변경 전파 비용·메모리와 재사용 이득 확인.
4. **조건부 대안**: Theta*/JPSW/SE2/NavMesh/표본 기반 방법을 요구·실험에 따라 좁힌다.
5. **교차 주행 재검증**: 선택한 가속안이 있어도 40회 폐기 같은 구조적 지연이 남는지 따로 측정한다.

1차 조사 당시에는 어느 방법도 채택하지 않았다. 이후 최신 합의로 축소 격자 방안만 개발 승인되었으며, 기존 A*를 유지하는 최적화와 다른 알고리즘 변경은
동일 입력·같은 품질 기준으로 분리 비교한다. 문헌의 속도 배수를 우리 성능 예상치로 사용하지 않는다.

## 5. 후속 상세 조사·실험의 공통 기준

- 고정 장면: ROBOT-6 첨부 장면, Yard/Large Lab, 짧은/긴 경로, 열린 방·좁은 문·원형 우회,
  prefer/avoid 없음·있음·겹침, hard zone, 도킹 방향/직사각형 몸체.
- 변경 장면: 이동/정차 peer, 반대 방향 교차, 새로운 목표, 맵·존 편집/텔레포터 맵 전환,
  로봇 대수 증가. 새 주행 일시정지의 경로 보존 계약과도 정합성 검토.
- cold/warm을 분리하고 고정 seed·여러 반복으로 p50/p95/p99, 최초 유효 경로 시간,
  총 명령→출발 시간, success/no-route/timeout/stale 폐기 수, 총 재계획 CPU를 측정.
- 비용 조회 수/히트율, 확장 셀·heap 크기, 전처리/IPC/탐색/후처리/최신 충돌 검증 시간,
  프로세스 RSS·캐시 한도·GC, 통신/tick 지연을 함께 측정.
- 길이만이 아니라 **동일한 원본 비용장에서 계산한 가중 경로 비용**, 몸체 최소 여유,
  hard zone 침범 0, 좁은 통로 도달 가능성, 목표 pose·추종 가능성을 비교.
- 원본 A*의 모든 후처리가 전역 최적이라고 가정하지 않는다. 작은 문제는 별도 정확 기준해로
  비교하고 큰 문제는 동등 조건의 기준선 대비 비용·실패율을 비교한다. 속도/오차 목표는 후속 합의.

이 절의 점수는 **실측 벤치마크가 아닌 프로젝트 적합성 예비 판단**이다. 논문에서 가져온 성능 점수가 아니며,
점수 1~3점 차이에 통계적 의미가 없다. 앞의 단계별 권고를 이 기준으로 보완하며 채택/구현 승인은 아니다.

### 평가 규칙

- S 탐색 응답 잠재력 40%: 초기 유효 경로의 빠른 반환 가능성. 1 불리~5 유리. 전처리 재사용 가능한 정상 운용을 기준으로 하며 cold-start는 별도 측정.
- D 동적 대응 구조 25%: 1 기본 지원 미흡, 2 갱신된 정적 스냅샷으로 재탐색, 3 특화된 부분 복구, 4 탐색 상태 증분 재사용, 5 예측 시각을 상태에 반영. 이는 기능 깊이의 점수이며 모든 환경에서 5가 4보다 빠르거나 안전하다는 의미가 아니다.
- W 존 비용 적합성 20%: 1 현행 의미와 부적합, 2 큰 변형 필요, 3 목적함수/표현 확장 필요, 4 비용 집계·근사·연속장 검증 필요, 5 현행 비음수 edge 비용/통행 금지 표현에 직접 적합.

### 판단과 튜닝 우선순위

1. **빠른 도입 비교: Weighted A* + 비용 타일 캐시**. w=1/1.25/1.5/2를 시험 후보로 두되 확정값이 아니다. w 증대가 모든 맵에서 더 빠름을 보장하지 않는다. ARA*는 최초 경로 이후 개선 예산을 별도 제한한다. 가중 존 비용과 heuristic inflation은 다른 계수다(S1).
2. **대형 맵 탐색량: 다중 해상도 + Weighted A***를 조합 후보로 둔다. 2배/4배 축소와 정밀 복원·금지영역 검증·실패 시 확장을 비교한다. HPA*는 정적 맵의 반복 장거리 질의에서 함께 비교(S2/S3). 조합 성능은 아직 측정하지 않아 점수 없음.
3. **움직이는 상대의 통과 시각까지 필수라면 Anytime SIPP 우선 조사**. 다른 상위 후보는 단독으로 이 요건을 만족하지 않는다. 예측 범위 2/5/10초 등은 실험 후보이며 지연·제동·불확실성에 맞춰야 한다. 범위 이후의 동적 안전을 자동 보장하지 않는다. 임의 prefer/avoid 비용을 도착 시간으로 사용하면 안 된다. 도착 시간과 누적 비용을 분리하고 대기 비용·상태 지배 조건을 재검토해야 하므로 원 논문 보장을 그대로 인용하지 않는다(S14).
4. **동일 목표·국소 변경 재사용은 D* Lite 비교**. 상대가 언제 지나가는지 계획하는 알고리즘은 아니다. peer 갱신 수/변경 edge 수가 많을 때 유지 비용을 측정(S4).
5. 최단 경로는 요구하지 않더라도 prefer를 무시하거나 지나친 우회·진동을 만드는 경로는 제외한다. 허용 우회/존 비용 편차는 후속 합의한다. 기존 prefer가 corridor 점유로 바뀌지 않도록 유지한다.

### 실제 순위를 확정할 측정 지표

- 주지표: **명령 수신 → 최신 동적 검증을 통과해 실제 사용할 수 있는 최초 경로까지의 p95/p99 시간**. 폐기된 결과의 빠른 계산은 성공으로 세지 않는다.
- 보조: 명령→출발 시간(교통 허가/안전한 대기로 분해), 계획 요청별 p50/p95/p99, stale 폐기율, timeout, 전체 재계획 CPU, 도달 성공률, 경로 진동.
- cold/warm 전처리 시간, 지도·존·목표 변경 복구 시간, peer 대수 증가에 따른 지연/RSS를 구분한다.
- ROBOT-6 재현 장면 및 다양한 지도에서 원해상도 몸체/금지 검증 통과를 확인하고, 동일 원본 비용장으로 prefer/avoid 반영을 평가한다.
- 성공률이 낮은 알고리즘이 성공한 소수 경로만으로 빠르게 보이지 않도록 실패/timeout을 함께 보고한다. 밀리초 목표와 성공률 기준은 아직 미합의이며 이번에는 실험하지 않았다.

추가 출처 S14: [Narayanan et al., Anytime Safe Interval Path Planning for Dynamic Environments, 2012](https://publications.ri.cmu.edu/storage/publications/pub_files/2012/10/asipp_iros12.pdf).
기존 SIPP에 anytime 탐색·시간 범위를 결합한 원 논문이며, 이 프로젝트의 연속 공간 가중 비용·직사각형 몸체 적용 성능을 입증한 자료는 아니다.
