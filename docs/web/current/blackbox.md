# 블랙박스 채널과 리플레이

2026-09-22 v2: PLAN-13·WEB-5·SRV-8의 블랙박스를 실제 누적 기록과 대형 지도 기준으로 재구성했다.
2026-09-21 v1의 사건 드롭다운 선행 조회는 더 이상 기본 진입 경로가 아니다.

`LiveEventChannel`과 `BlackboxEventChannel`은 같은 Snapshot/구독 계약을 사용한다.
main의 활성 소스가 공통 맵·로봇 목록·속성·런타임 렌더러에 데이터를 제공한다.
라이브 룸은 백그라운드에서 수신할 수 있지만 블랙박스 화면에는 기록 채널만 적용한다.
과거 연결 상태는 현재 브라우저 연결 상태로 덮어쓰지 않으며 대기 시간도 replay clock을 쓴다.

## 사용

1. 맵을 선택하고 상단 **블랙박스**를 열면 남아 있는 최신 기록의 최근 약 30초를 자동으로 연다.
   운용 명령 사건이 없는 대기 상태도 기록 checkpoint가 있으면 지도와 로봇을 표시한다.
2. 시작·끝 날짜와 시각으로 구간을 바꾸고 **시간 구간 조회**를 누른다.
   선택한 시간 범위가 재생 시계의 기준이며 일반 frame도 포함해 위치·상태·경로를 복원한다.
3. 재생·일시정지, 배속, seek와 사건 이동을 사용한다. `RECORDED`와 기록 시각으로 라이브 화면과 구분한다.
   구형 사건 시작·끝 선택은 기본 화면에서 숨겨 서로 다른 범위가 동시에 표시되지 않게 했다.
4. 블랙박스를 닫으면 라이브 자산·현재 상태를 다시 동기화한 뒤 운용으로 돌아간다.
   진입·종료 자체는 실제 로봇 정지·취소·제어해제 명령이 아니다.

기록된 원본 PNG를 먼저 표시한다. 읽기 전용 재생을 위해 100 MB occupancy와 100 MB inflated 격자를
먼저 내려받거나 청사진 생성을 기다리지 않는다. 실제 과거 PNG가 준비되기 전에는 라이브 배경을
대신 보여주지 않는다. 지도 맞춤은 하단 타임라인을 제외한 보이는 영역을 사용한다.

## 범위·오류·조회 제한

`catalog`에서 최신 기록 범위를 찾고 `window`의 checkpoint와 frame 페이지를 연결한다.
한 구간의 응답 누적은 64 MiB·10,000 frame 한도로 제한하며 넘으면 더 짧은 구간을 요청하도록 안내한다.
기록 공백과 서버 조회 제한은 화면에 표시한다. checkpoint·원본 자산 누락이나 조회 실패를
구형 24시간 전체 조회나 현재 지도/로봇으로 숨기지 않는다. 정상 범위를 다시 열면 이전 오류를 지운다.

## 기록 관리

관리 화면의 **전체 블랙박스 기록 삭제**는 모든 맵·출처의 블랙박스만 대상으로 한다.
확인창에서 취소할 수 있으며 운영 DB·로봇 위치·진행 중 명령을 초기화하지 않는다.
삭제 후 기록 세대가 바뀌면 다른 탭의 리플레이도 정지하고 이전 장면·사건·trace를 비운다.
새 checkpoint가 생기면 최근 가용 시작 시각부터 다시 자동 진입한다.
물리 파일 정리 미완료는 부분 실패로 구분하고 서버가 반환한 원인을 표시한다.

## 안전 경계

- mode/세대 검사로 지연 HTTP·자산 응답과 이전 seek/복귀 작업을 무효화한다.
- 진입 시 미완료 운용 확인/timeout 세대를 바꾸고 편집 초안을 비운다.
- 중앙 `send()`에서 블랙박스와 라이브 재동기화 중 운용·편집 전송을 막는다.
- 공통 화면은 활성 채널의 상태만 읽는다. 별도 리플레이 로봇 렌더러를 만들지 않는다.
- 블랙박스의 맵 전환은 라이브 복귀 후 수행한다. 재생 일시정지는 화면 시계만 정지한다.

## 검증

- `web-client/src/blackbox.test.ts`, `blackbox.v2.test.ts`: 선택 시간 경계, idle 장면, cursor 페이지,
  오류 후 재조회, 지연 응답 무효화, 순차 재생과 seek 일치.
- `scripts/check_blackbox_v2.ts`: 격리된 실제 두 로봇의 이동·수동 정지/재개를 기록하고,
  10000×10000 과거 PNG가 실제 canvas에 그려지는지와 paused/completed frame의 좌표·상태가
  화면에 정확히 일치하는지 검사한다. 재생·정지·배속·라이브 제어 차단도 검증한다.
- 기존 `web-client/check_blackbox.ts`의 모의 API·1픽셀 PNG 검사는 실제 지도 검증 근거를 대신하지 않는다.

실제 PNG 누락 오류·복구 재진입도 통과했다. 결과는 WEB-5 v2에 첨부한다.

2026-09-22 운영 반영: 웹·두 FMS·두 로봇의 PM2 프로세스 5개를 재기동했다.

API는 모두 200, page error는 0건이었다. 근거는 관련 v2 카드에 첨부한다.


## 2026-09-23 대형 배경맵 표시 보완

사용자는 새로고침 뒤에도 배경맵이 보이지 않는다고 보고했다. 독립 Chromium의 새 Large Lab
세션에서는 현상을 재현하지 못했으나 기록된 10000×10000 PNG의 대형 비트맵 처리 부담과
이전 자산 요청의 늦은 오류가 최신 자산 표시를 무효화할 수 있는 경합을 확인·보완했다.

보관 PNG를 `createImageBitmap`으로 디코딩할 때 표시용 비트맵의 긴 변을 최대 4096픽셀로
제한한다. 원본 파일·지도 축척·좌표·장면 크기는 변경하지 않고 원래 지도 범위에 맞춰 그린다.
API를 지원하지 않는 브라우저는 기존 이미지 로더를 사용한다. 교체·화면 전환·늦은 응답의
ImageBitmap을 해제하며, 성공과 실패 모두 현재 자산 요청 세대에 해당할 때만 적용한다.
보관 자산이 실제로 없으면 명시적인 오류를 보여주며 현재 지도로 임의 대체하지 않는다.

격리된 실제 로봇 2대·서버·Chromium 검사에서 원본 기록과 디코딩된 지도의 좌표 범위를
확인하고, 화면 픽셀을 이미지 기준 렌더링과 비교했다. 진입·seek·창 크기 변경·이미지 누락 후
복구에서 약98.4% 픽셀이 일치했다(나머지는 로봇/경로/구역 등 오버레이). 페이지 오류 0건.
근거: `/tmp/fms-blackbox-v2-sYOX3v/result.json`, `paused-replay.png`, `missing-map-error.png`.

웹 번들을 현재 서비스에 반영한 뒤 LAN 주소의 실제 페이지에서도 4096×4096 표시 비트맵,
10000×10000 지도 좌표 범위, 밝고 어두운 배경 영역을 확인했다.
근거: `/tmp/fms-stepback-replay-live.json`, `/tmp/fms-stepback-replay-live.png`.
