# 로봇 운용과 상태 표시

운용 모드에서 로봇을 선택하고 이동 목적지 또는 충전소를 지정한다.
이동·도킹은 편집 초안 저장과 달리 즉시 명령 요청이다. 취소는 현재 명령 ID를 대상으로 한다.

commandAck는 전송 확인이다. accepted/running/completed/cancelled/rejected/failed 등
실제 결과는 로봇 보고에서 동기화한다. 새로고침 후에도 현재 룸 상태로 결과를 표시한다.
WebSocket 단절 중에는 명령을 잠그고 재연결한다.

## 런타임 패널

로봇 탭에서 작업·연결·운영 참여·실제 주행을 분리해 표시하고,
대기 원인·리소스·차단 로봇·대기 시간·마지막 보고를 확인한다.
지도에서는 운영 제외와 연결 단절을 구분한다.

구역에는 실제 점유, 진입 예약, 대기열을 구분한다.
점유 해제는 확인창을 거쳐 해당 로봇의 운영 제외와 함께 처리한다.
로봇 단위 **운영 제외**는 해당 로봇의 모든 논리 점유·예약·대기열(텔레포터 포함)을 강제 해제하고
진행 작업을 무효화한다. 확인창에서 전체 해제 범위를 안내한다. 실제 몸체는 장애물로 남으며
위치·상태 보고를 계속 표시한다. **운영 재개**는 명시적으로 요청하고 현재 상태를 다시 동기화한다.
개별 점유의 **선택 해제**는 선택한 기록을 해제하며 해당 로봇을 운영 제외로 전환하는 별도 동작이다.
화면의 성공 표시는 runtimeAck를 따르고 실제 정책은 [운영 복구](../../fms/current/runtime-recovery.md)가 기준이다.

운영 제외된 연결 가상 로봇에도 `테스트 위치 지정`을 표시한다. 위치 지정은 논리 점유를
정리하고 새 pose를 확인하지만 운영 재개를 암묵적으로 수행하지 않는다. 실기 로봇에는
이 메뉴를 제공하지 않으며, 연결되지 않은 로봇은 위치 지정을 거부한다.

미리보기 맵에서는 편집·운용을 실행하지 않는다.
실제 이동 검사는 유휴 가상 로봇을 준비한 후 순차 수행한다.

## 2026-09-22 HTTP 운용 명령 전송 수정 (WEB-5)

LAN HTTP 접속에서는 `crypto.randomUUID`가 제공되지 않아 일반 이동·편집 명령이
요청 ID 생성 중 예외로 중단됐다. 별도 requestId를 사용하는 테스트 위치 지정과 운영 재개는
성공하므로 재개 후 이동만 무반응으로 보였다. 공통 `send()`가 기존 `runtimeRequestId`를
사용하도록 수정했다. `web-client/check_blackbox.ts`에서 randomUUID가 없는 브라우저의
이동 전송과 기존 리플레이 차단·복귀 회귀를 검증하고 운영 웹 PM2를 재기동했다.
실제 로봇의 추가 이동은 사용자 웹 검수로 남긴다.

## 2026-09-22 로봇 일시정지와 이벤트 콘솔

운영 런타임 영역에서 로봇을 복수 선택해 [주행 일시정지·재개](../../concept/current/operator-motion-pause.md)를 요청한다.
적용 ACK와 로봇별 부분 실패를 표시한다. [이벤트 콘솔](robot-event-console.md)은 로봇·기간·수준·종류 필터,
화면 따라가기 정지, 과거 조회와 JSON/trace 상세를 제공한다. 화면 갱신 정지는 주행을 멈추지 않는다.
