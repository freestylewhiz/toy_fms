# 배치 규칙

사용자가 맵에 그릴 때 지키면 좋은 규칙. 구현 전 설계 메모.

---

## 1. 포탈

`corridor` / `complex` 는 폴리곤만으로 부족하다.
**포탈** = 존 경계와 외부 자유공간이 맞닿는 입구. 토큰 요청은 포탈 앞에서 한다.

- 복도 양끝에 포탈 2개 (일반적).
- 존 한가운데에서 토큰을 요청하면 이미 들어간 것과 같다. 금지.
- 로봇이 포탈에 `LOOKAHEAD_S` 거리만큼 다가오면 요청. 거절이면 포탈 앞에서 정지. 경로를 지우지 않는다.

---

## 2. 겹침 우선순위

같은 픽셀에 여러 존이 있으면 강한 쪽이 이긴다.

```
forbidden  >  corridor / complex  >  avoid / prefer  >  (없음)
```

- forbidden ∩ 무엇이든 → 금지.
- corridor ∩ prefer → 토큰 + 레일이 이긴다. prefer 비용은 존 밖 접근 경로에만 의미 있다.
- avoid ∩ prefer → 그리기 실수. UI가 경고. 해석이 필요하면 **avoid 우선** (더 보수).

용량 존끼리 겹치면 하나의 뮤텍스 그룹으로 합치는 편이 안전하다 (Open-RMF mutex group 과 같음).
교차로 네 레인을 한 그룹에 넣으면 교차로에 한 대만 들어간다.

---

## 3. 그리는 크기

- **corridor**: 벽 사이 통로만. 홀까지 크게 그리면 홀 전체가 용량 1이 된다.
- **complex**: 실제로 한 대만 원하는 작업 반경. 너무 크면 처리량이 죽는다.
- **prefer**: 통로 **중심 밴드**. 벽까지 칠하면 비용이 넓게 퍼져 의미가 없다.
- **avoid**: 사람 동선·테이블. 유일한 통로를 전부 avoid 로 칠하지 않는다 (그래도 통과는 되지만 숫자만 커진다).
- **forbidden**: 물리 벽과 맞닿게. 틈을 남기면 A*가 틈으로 들어간다.

---

## 4. 로봇이 존을 아는 방법

FMS가 존 레이어를 브로드캐스트한다 (장애물 스냅샷과 같은 채널이거나 별도).

| 레이어 | 로봇 로컬 |
|--------|-----------|
| forbidden | extra occupancy lethal |
| avoid / prefer | A* 가중 그리드 |
| corridor / complex | 폴리곤은 알되, **토큰 없이 들어가지 않음**. 게이트는 FMS |

로봇이 용량을 로컬에서 세지 않는다. 카운터의 권한은 FMS.

---

## 5. 존이 없는 맵

시드 맵은 존 0개여도 된다.
그때 전 칸이 v2 자유 공간이다.
복도 교착이 반복되면 **그때 사용자가 corridor 를 그린다.**
알고리즘이 복도를 자동 추출하는 것은 후순위 (오탐이 운영 규칙과 어긋남).
