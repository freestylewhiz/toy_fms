# 사용자 정의 트래픽 존

맵 위에 **사람이 그려 넣는 시맨틱 리소스**. 자율주행이 기하만으로 풀지 못하는 구간을, 운영자의 판단으로 문법화한다.

이 폴더는 “존이 있을 때 무엇을 강제하는가”만 다룬다.
존이 **없는** 열린 공간의 교행·대기는 [`../traffic_control_v2/`](../traffic_control_v2/README.md) 가 담당한다.

---

## 한 줄

> 좁은 복도, 혼잡, 금지, 선호/비선호는 A*가 발견하는 것이 아니라 **사용자가 맵에 선언하는 자원**이다.
> 선언되지 않은 칸은 균일 비용의 자유 공간이고, 로봇은 거기서 A→B 를 스스로 탄다.

---

## 왜 별도 리소스인가

자율 플래너는 폭·혼잡·업무 규칙을 모른다.

- 폭이 `2 × TRAFFIC_SEP` 보다 좁은 복도는 우회 자유도가 0이다. 한가운데에서 A* 실패를 기다리면 후진이 된다.
- 사람이 많은 로비는 기하적으로는 넓어도, 한 대씩만 들어가게 하고 싶을 수 있다.
- 선호 통로는 “최단”이 아니라 “운영이 원하는 길”이다.

이런 것은 **토폴로지·정책**이지 센서 반응이 아니다. 그래서 맵 에셋으로 둔다.

산업적으로도 같은 층이 있다.

| 제품/논문 | 대응 |
|-----------|------|
| Open-RMF mutex group | 웨이포인트/레인에 상호배제 그룹. 한 번에 한 로봇만 lock |
| Open-RMF lane cost / speed limit | 낮은 속도 = 높은 비용 → 선호 레인 유도 |
| Layered costmap (Jeong et al., 2022) | prohibition / lane / region-ticket 필터 |
| AGV 고정폐색 | 구간 용량 1 |

## 존 종류 (카탈로그)

| id | 이름 | 하는 일 | 로봇 모드 |
|----|------|---------|-----------|
| `corridor` | 긴 복도 | 용량 1, 또는 2대 교행이 아슬하면 지정 레일 | 진입 전 토큰. 안에서는 추종 가능 |
| `complex` | 복잡한 영역 | 사람·작업이 많아 1대씩 진입 | 용량 1 뮤텍스. 경로는 자율이어도 됨 |
| `forbidden` | 금지 구역 | 절대 진입 불가 | occupancy lethal. A* 불가 |
| `avoid` | 비선호 구역 | 가능하면 경로에 넣지 않음 | A* 가중 ↑ (통과는 가능) |
| `prefer` | 선호 구역 | 가능하면 이 길로 | A* 가중 ↓ (강제 추종 아님) |

상세: [`01_types.md`](./01_types.md). 배치·겹침 규칙: [`02_placement.md`](./02_placement.md).

---

## 자율 공간과의 경계

```
맵
 ├─ forbidden     → 벽과 동일 (계획 공간에서 삭제)
 ├─ corridor/complex → 포탈에서 FMS 토큰. 존 문법
 ├─ prefer / avoid   → 비용 맵만. 토큰 없음
 └─ (표시 없음)      → traffic_control_v2 자유 주행
```

존이 덮지 않은 픽셀에 v0 전역 회랑 임대를 씌우지 않는다.
그 픽셀에서의 겹침은 **시공간 양보**(대기·감속·짧은 교행)로 푼다.
