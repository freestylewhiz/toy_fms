# FMS 힌트 — 일시적 선호 구역

v0 F3: FMS는 경로 제공자가 아니다.
그래도 “큰 우회를 말자”면 가끔 **좌표가 있는 힌트**가 싸다.
이 문서는 그 힌트를 **사용자 `prefer` 와 같은 비용 레이어**로만 취급한다고 못 박는다.

---

## 1. 명령이 아니라 비용

```
힌트 ≠ DriveCommand
힌트 = 짧은 폴리라인 + cost_scale < 1  (수 초 TTL)
```

로봇 A*는 힌트를 일반 `prefer` 존처럼 더한다.
막히거나, 이탈하거나, 더 싼 길이 있으면 **무시해도 된다.**
따라가라는 토큰이 없다.

사용자 `prefer` 와의 차이:

| | 사용자 prefer | FMS 힌트 |
|--|---------------|----------|
| 누가 | 맵 에디터 | 분쟁 중인 FMS |
| 수명 | 맵과 같음 | 충돌이 사라지면 삭제 |
| 범위 | 운영이 원하는 통로 | 이번 겹침을 푸는 짧은 띠 |

---

## 2. 언제 켜나

L1~L3 로 안 열리고, 로봇의 자율 우회가 **대기보다 훨씬 길 때**.

예: 상대 로컬 플랜이 홀을 가로질러 벽처럼 보여 A*가 건물 밖으로 도는 경우.
힌트는 “상대가 지나간 뒤 그 복도를 그대로 써”가 아니라,
“충돌 지점 **옆**의 1 차선만 잠깐 싸게” 정도여야 한다.

힌트 생성 후보 (구현 시 고름):

1. 두 로컬 플랜의 충돌 세그먼트에 수직인 짧은 평행 이동 (교행 레인).
2. 승자 경로의 왼/오른쪽 오프셋.
3. 사용자 `prefer` 가 근처에 있으면 그걸 연장.

FMS가 맵 장애물로 **안전 판정**하지 않는다는 v0 P2 는 유지한다.
힌트는 비용일 뿐이고, 로봇 occupancy 가 거부할 수 있다.
막힌 힌트를 보고 다른 좌표를 발명하지 않는다.

---

## 3. 언제 끄나

- 두 로컬 플랜의 시공간 겹침이 사라짐.
- TTL (예: 8초).
- 힌트를 받은 로봇이 목표에 도착하거나 cancel.
- 사용자 `forbidden` 과 겹치면 즉시 폐기.

---

## 4. 복도에는 쓰지 않는다

좁은 복도에 힌트 레인을 두 줄 까는 것은 `corridor` + `rail` 의 일이다.
FMS가 실시간으로 레일을 발명하면 F1/F3 이 다시 열린다.
복도는 사용자가 그린다.
