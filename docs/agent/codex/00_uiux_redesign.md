# Codex UI/UX 재설계안

최종 갱신: 2026-09-14

## 목표

맵 편집자의 핵심 동선을 `맵 선택 → 작업 모드 선택 → 도구 선택 → 맵 조작 → 속성 확인 → 저장`으로 단순화한다.

현재 구현된 Canvas, Colyseus 메시지, gRPC 로봇 명령, SQLite 저장은 유지한다. 이번 재설계에서 통신 프로토콜이나 Room 스키마를 변경하지 않는다.

## 현재 문제

- 좌측 도구와 우측 정보가 모두 같은 시각적 중요도를 가져 처음 진입 시 무엇을 해야 하는지 약하다.
- `운용 / 현장 배치 / VDA 배치`의 차이는 있지만 각 모드에서 작업 순서와 위험도가 충분히 드러나지 않는다.
- 맵 이름·좌표계·현재 저장 상태가 상단에 명확히 나타나지 않는다.
- 우측 도크가 레이어, 로봇, 목록, Inspector를 한 번에 보여줘 스크롤이 길고 선택 후 속성 편집 흐름이 끊긴다.
- 맵 전환 시 현재 SQLite/Room 데이터가 다른 맵에 잘못 쓰이지 않도록, 서버 계약을 바꾸기 전에는 비-yard 맵을 읽기 전용으로 보여줘야 한다.

## 새 정보구조

### 1. 상단바

- 제품명과 현재 맵 컨텍스트
- 맵 ID, 버전, 좌표계 요약
- 3개 작업 모드
- 연결 상태와 선택된 로봇

### 2. 좌측 도구 레일

- 현재 모드에 해당하는 도구만 노출
- 운용: 로봇 선택, 이동, 도킹
- 현장: waypoint, charger, obstacle, scene zone
- VDA: node, edge, station, zoneSet, portal, rail
- 보기: Grid/occupancy

### 3. 중앙 Canvas

- 월드 좌표 기반 pan/zoom 유지
- 좌상단에 현재 맵과 모드 설명 HUD
- 좌하단에 occupancy 범례
- 하단에 편집 세션 확인/취소

### 4. 우측 도크

- 운용 상태: 연결된 로봇과 명령 취소
- 레이어: 시각적 레이어 표시/숨김
- 리소스: Outliner 목록
- 선택 속성: 선택된 리소스의 Inspector

현재 DOM ID는 유지해 기존 클라이언트 이벤트와 서버 메시지를 보호한다. 시각적 그룹과 설명만 재구성한다.

## 맵 전환 원칙

현재 서버는 `yard` 단일 편집 맵과 컴파일 타임 occupancy 상수를 사용한다. 이번 단계에서는 UI 맵 카탈로그를 도입해 `yard`와 `1st_floor`의 PNG/occupancy/크기를 실제로 전환한다. 단, 현재 Room 계약을 보존해야 하므로 `1st_floor`는 로봇 위치만 볼 수 있는 읽기 전용 미리보기이며 리소스는 노출하지 않는다.

맵별 편집 데이터까지 완전히 분리하는 작업은 다음 단계에서 처리한다.

1. ~~맵 카탈로그와 런타임 맵 컨텍스트 도입~~ 완료
2. ~~occupancy/PNG/크기 로딩을 맵별로 분리~~ 완료
3. SQLite에 map_id를 리소스 전반에 적용
4. 기존 Room 메시지 의미를 유지한 채 서버 내부 active map을 전환
5. 가상 로봇 맵 변경은 gRPC 계약 변경 없이 재연결/세션 규약으로 결정

## 구현 순서

1. HTML 정보구조와 CSS 도크 계층 재설계
2. 현재 모드 설명과 맵 컨텍스트 표시 추가
3. 기존 편집 세션 확인/취소 동선 유지 및 시인성 강화
4. 브라우저 smoke: 모드 전환, 도구 전환, 리소스 선택, 편집 세션 표시
5. 맵 카탈로그/전환 구현: `yard` 편집 + `1st_floor` read-only preview 완료
