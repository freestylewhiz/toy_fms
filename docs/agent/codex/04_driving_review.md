# 주행모드 통합 리뷰 — 2026-09-14

## 범위와 분담

총괄이 계획·공유 계약·리소스 배치·통합 검증을 담당하고, 서버/가상 로봇/웹을
각 서브 에이전트에 분담했다. 기존 Colyseus + gRPC와 local_plan_v1을 유지하면서
편집 존을 실제 계획·속도·용량 제어에 연결했다. 이전 UI 단계 문서의
“트래픽 변경 비목표”는 이 후속 주행 작업에는 적용하지 않는다.

v2 문서의 ORCA/시공간 계획과 VDA 주문·레일 추종은 구현 범위에 포함하지 않았다.
구체적인 지원 범위와 실행 방법은 [주행 안내](../../user/driving.md)를 참조한다.

## 리뷰에서 발견해 수정한 문제

- wp-3이 벽 안에 있어 기본 smoke 실패 → 세로 복도 중심 x=1248로 이동.
- 편집 존이 로봇에 전달되지 않음 → protobuf semantic_snapshot 및 변경 전파.
- 선호 비용을 무시하는 A* 휴리스틱/경로 단순화 → 비용 보존과 최소 비용 휴리스틱.
- 멀리 있는 STOP 존 때문에 모든 로봇 정지 → 현재 몸체/다음 이동점으로 범위 제한.
- 허가 없는 진입, 허가 갱신 누락 → 기본 STOP과 heartbeat 만료 검사.
- 오프라인 점유자 소실, 오래된 대기 요청 → 물리 점유 유지와 대기열 정리.
- 금지 존 실시간 추가 후 임무 소실/재개 실패 → 실제 이동 차단 및 임무 보존.
- 선택 이후 로봇이 출발해도 취소 버튼 비활성 → 상태 갱신마다 버튼 재계산.

## 검증 결과

- `bun test`: 39개 통과. 실제 protobuf 직렬화, 서버 gate↔로봇 통합, 경계 대기,
  허가 만료, 속도 제한, 금지 존 실시간 변경·복구 포함.
- `bun run smoke`: 기본 맵·목적지 경로 검사 통과.
- `bun run check:driving:resources`: 현재 SQLite의 존·장애물을 반영해 두 로봇에서
  주행용 목적지 6개와 기존 충전소까지 총 14개 경로 확인.
- `bun run test:traffic-v1`: 기존 정책/기하 테스트와 주행·VACATE 시뮬레이션 통과.
- 서버·로봇·웹 Bun 번들 빌드 통과. TypeScript 전체 타입 검사를 대신하지는 않는다.
- 실제 네트워크/웹 E2E는 미검증: 샌드박스에서 gRPC 및 loopback listen이 거부됨.
  Playwright 로컬 의존성도 `chromium-bidi`가 누락되어 브라우저 검사를 실행하지 못함.

현재 SQLite는 setup 전에 JSON으로 백업했다. 주행용 리소스 배치는
`bun run setup:driving`으로 재현할 수 있다. 실제 서비스 시작/브라우저 검증 완료를
이 리뷰의 통과 항목으로 간주하지 않는다.
