# 가상 로봇 주행

가상 로봇은 virtual-robot/ 프로세스다. 기본 `robot-1`, `robot-2`를 실행하며 물리 로봇 ID는 맵을 바꾸어도 유지한다. Large Lab 전용 로봇 프로세스를 같은 ID로 추가 실행하지 않는다.
전체 개발 실행은 루트 `bun run pm2:start`를 사용한다. 각 프로세스는 Bun으로 실행되고 PM2가 재시작을 관리한다.
현재 보고 주행 방식은 free_navigation, 경로 계획 주체는 robot이다.

## 맵·계획·추종

yard occupancy는 1600×1200 row-major 바이트 배열이며 1은 주행 가능이다.
정적 계획 그리드는 8 px inflate를 사용한다.
몸체는 길이 16×폭 10 px이고 충돌 검사에서는 회전된 몸체 형상을 확인한다.
기본 속도는 12 px/s(0.60 m/s), 각속도 상한 π/2 rad/s, tick은 50 ms다.

계획은 8방향 A*와 경로 단순화를 사용한다. 동적 장애물과 금지 존을 반영하고,
선호 존은 몸체가 경계에서 떨어진 내부일수록 유리하게, 회피 존은 외곽 완충 띠부터
내부 깊이까지 점진적으로 불리하게 평가한다. 비용은 단순화 과정에서도 유지한다.
12px 코너 완화는 몸체·하드 존·비용 검사를 통과할 때만 적용한다.
목적지 도달 뒤 최종 각도로 정렬한다. 완료 거리 기준은 0.5 px 미만, 각도 허용치는 3도다.
move와 dock은 목적지 pose를 따르며 물리 충전기 결합 동작은 구현하지 않는다.

## 동기화와 트래픽

장애물·시맨틱 스냅샷 갱신은 로봇 계획에 반영된다.
배치 질의는 현재 몸체와 앞으로 약 5초 경로에 장애물이 겹치는지 검사한다.
local_plan_v1에서는 상대 몸체·단기 경로를 받아 회피를 계획하며
FMS REROUTE/VACATE 요청에 자신의 계획·이동 흔적으로 대응한다.
서버와 로봇의 TRAFFIC_POLICY_ID는 같아야 한다.

SIM_PEER_SENSING_DEFAULT는 시뮬레이터 센서 대용 정보 전달 설정이다.
FMS가 전하는 상대 위치가 실제 라이다 센서 구현을 의미하지 않는다.

## 2026-09-21 재계획·통신 지연 수정 (ROBOT-6)

빈/동일 peer 경로 보고만으로 정상 경로를 반복 재계획하거나 HOLD로 바꾸지 않는다.
짧은 경로의 실제 목표 재시도와 변경된 장애물의 경로 차단을 구분한다.
실행 프로세스는 A*를 단일 계획 Worker(별도 Bun 자식 프로세스/IPC)로 분리하며 기본 5초 계산 예산을 적용한다.
초기 Web Worker 구현은 Bun 1.3.13에서 빠른 취소/재생성 중 로봇 부모 프로세스의 segmentation fault가
격리 텔레포터 검사에서 관측되어 교체했다. 계획 프로세스는 로봇이 생성·종료하며 별도 systemd/서비스가 아니다.
제어·연결 상실, 취소, 위치 지정, 맵 전환은 이전 계산을 무효화한다.
주변 정보가 반복 갱신될 때마다 계산을 취소하지 않고 결과를 최신 몸체·하드 존 기준으로
재검사한다. 오래된 계획의 적용과 고빈도 갱신에 의한 계산 기아를 함께 막는다.
실제 비동기 재계획 중에는 위치를 유지해 오래된 시작점으로 되돌아가는 경로 적용을 막는다.
계산 timeout/no-route/프로세스 오류/취소/오래된 결과는 trace의 실패 사유로 구분한다.
동적 장애물 마스크는 같은 맵에서 버퍼를 재사용하고 이전에 수정한 영역만 비운다.

주행 추종·물리 충돌 검사는 기존 컨트롤러에서 계속 수행한다. Worker 사용은 새 트래픽
알고리즘이나 무조건적인 주행 성공 보장이 아니다. 경로 불가·트래픽 정체는 계속 표현한다.
계획 사유·단계·시간·결과를 operation ID에 연결된 블랙박스 trace로 남긴다.

검증: `planning.test.ts`, `controller.test.ts`, `shared/obstacles.test.ts`,
격리 두 로봇 주행 `scripts/check_blackbox_traffic.ts`.

## 2026-09-23 짧은 step-back 반복

사용자 요청으로 VACATE/자체 우회 실패 후퇴를 한 번의 3.6m 경로에서 **0.5m 단위 시도**로
변경했다. 이동 거리는 원본 지도 해상도로 올림한다: `ceil(50 / PIXEL_CM)` 픽셀.
현재 모든 운용 맵은 5cm/px이므로 10px=0.5m다. 예를 들어 3cm/px에서는 17px=0.51m다.
coarse 계획 격자는 이 반올림 기준에 사용하지 않는다. 설정은 `shared/constants.ts`의
`STEP_BACK_DISTANCE_PX`, `STEP_BACK_WAIT_MS`에서 관리한다.

각 구간에 도달하면 **5초** 대기한 뒤 최신 상대 몸체·단기 경로를 개별적으로 확인한다.
초기 1초 안은 다른 로봇의 우회 계산 시간을 주자는 사용자 후속 지시로 5초로 늘렸다.
공간이 확보되면 원래 목적지로 재계획하고, 계속 겹치면 다음 구간을 시도한다.
관측이 1초보다 오래되었으면 추가 구간을 시작하지 않고 재확인한다. 후퇴 도중 실제 이동이
막힌 경우에도 5초 대기 후 미완료 구간을 다시 시도하며, 지나지 않은 부분을 완료로 계산하지 않는다.

후퇴 시작 시 보관된 전체 이동 흔적을 고정하고 그 경로를 순서대로 소진한다.
후퇴 중 새 흔적을 추가하지 않으며, 종료·취소·명령 교체 시 실제 소진 지점까지 이력을 정리해
다음 후퇴에서 앞으로 되돌아가는 현상을 방지한다. 남은 흔적이 0.5m보다 짧으면 그 지점까지만
이동하며 모두 소진하면 대기한다. 3.6m의 별도 총거리 상한은 제거했다.

원래 commandId를 유지하며 해당 ID로 취소할 수 있다. 같은/새 우회 round가 이미 진행 중인
구간을 다시 시작하지 않는다. 수동 정지, 식별된 교통 STOP, 제어·연결 경계, 몸체 충돌·금지 존
검사는 유지한다. 후퇴는 이전 궤적을 따라가는 방식이며 고정 자세의 물리 후진 구현은 아니다.

검증: `shared/traffic/localPlan.test.ts`, `virtual-robot/src/controller.test.ts`,
`virtual-robot/src/stepBack.test.ts`. 전체 312개 테스트 통과 후 최종 보완 부분은 관련 검사로
재검증했다. 사용자 재기동 승인 후 PM2 가상 로봇 2대에 적용했으며 양쪽 위치·방향 변화 없이
connected/controlReady/idle/stationary를 확인했다. 새 주행 명령은 보내지 않았다.
근거: `/tmp/fms-stepback-before-restart.json`, `/tmp/fms-stepback-after-restart.json`.

## 2026-09-23 상대 경로 회피의 우회 거리 제한

일시적인 상대 경로 겹침 때문에 지나치게 큰 우회를 선택하지 않도록 사용자와 다음 기준을 합의했다.
물리적 주행 거리(m)를 사용하며 prefer/avoid 가중 비용과 표시용 단순화 경로의 길이를 기준으로 삼지 않는다.

`허용 거리 = 원래 남은 거리 + min(5m, max(1m, 원래 남은 거리 × 0.3))`

설정은 [detourBudget.ts](../../../shared/traffic/detourBudget.ts)의 `DETOUR_BUDGET_RATIO`,
`DETOUR_BUDGET_MIN_M`, `DETOUR_BUDGET_MAX_M`에 있다. 예를 들어 2m/10m/30m가 남으면
각각 3m/13m/35m까지 허용한다. 경계값과 같은 길이는 허용한다.

명령에서 처음 채택한 글로벌 주행 경로를 복사해 별도로 보존한다. 이후 우회 경로로 덮어쓰지
않으며 새 명령·취소·맵/제어 경계에서 정리한다. 초기 경로 자체는 기존 플래너가 명령 시작
시점의 peer 정보까지 반영해 만든 경로다. peer가 없는 별도 가상 글로벌 경로를 추가 계산하는 정책은 아니다.

현재 위치를 원래 경로에 투영해 남은 구간을 구하고, 벗어나 있으면 복귀 연결 거리도 포함한다.
이미 진행한 구간으로 잘못 투영하지 않도록 진행량을 추적하며 실제 후퇴 거리는 반영한다.
복귀 연결과 남은 기준 구간은 지도 몸체 검사·현재 고정 장애물·금지 존·텔레포터 제약을 검사한다.
이 기준 계산에서는 상대 몸체/예측 경로를 제외하지만 후보 계획과 실제 이동의 충돌 검사는 유지한다.
안전한 연결을 확인할 수 없거나 완전한 기준 경로가 없으면 큰 우회를 임의로 허용하지 않는다.

FMS REROUTE와 로봇 자체 peer 회피에 같은 검사를 적용한다. 거절 시 FMS 요청에는 NONE으로
답하고 후속 VACATE를 기다리며, 자체 회피는 기존 이동 흔적을 따라 약 0.5m 후퇴·5초 대기를
시도한다. 후퇴가 불가능하면 대기한다. 후퇴 종료 재계획과 거절 후 일반 재시도에도 제한을
적용해 우회 제한을 건너뛰지 않도록 한다. 실제 정적 주행 환경 변경은 별도 재계획으로 처리하며,
같은 환경 스냅샷을 다시 받는 것만으로 거절 상태를 해제하지 않는다.

`navigation.detour_rejected` 이벤트에 `baselineLengthM`, `candidateLengthM`, `allowedLengthM`,
거절 사유와 후속 처리를 기록한다. 콘솔은 자연어로 거리·목표 이름·commandId를 표시하고
JSON 원문은 기존 상세 보기에서 확인한다. 기준을 계산하지 못한 값은 0m로 오인하지 않도록
확인 불가로 표시한다. 이번 변경은 코드 수정이며 운영 로봇 재기동 적용은 별도다.

검증: 최종 `bun test` **330개/55개 파일 통과**, 로봇·웹 Bun 번들 빌드 통과.
[거리 계산 검사](../../../shared/traffic/detourBudget.test.ts),
[독립 거리 회귀 검사](../../../shared/traffic/detourBudget.regression.test.ts),
[독립 컨트롤러 회귀 검사](../../../virtual-robot/src/detourBudget.regression.test.ts)에서
경계값·비율·최소/최대 허용량, 기준 복사 보존, 연속 우회, 취소 후 늦은 결과, 동일 스냅샷,
실제 장애물 변경, VACATE 복귀, 자체 우회 거절 후 0.5m·5초 대기를 검증했다.

실행 중 로봇에 새 주행 명령을 보내거나 재기동하지 않았다.
