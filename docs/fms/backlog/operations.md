# 실기 운영 복구 후속 논의

상태: 논의 후보. 현행 수동 해제·운영 제외 규칙은 [current](../current/runtime-recovery.md)를 유지한다.

- 실제 센서와 마지막 보고가 충돌할 때 오프라인 로봇의 장애물 위치를 누가, 어떤 근거로 해소하는가?
- 재활성화 시 idle/정지/위치 외에 실기 안전 신호·점유 대조를 추가할 것인가?

제안 구현 전에 실제 운영 시나리오와 복구 승인 주체를 정한다.
지금의 물리 정지와 운영 권한 분리는 유지해야 한다.
운영 제외 시 논리 점유·예약·대기열 전체 해제는 2026-09-17 사용자가 승인했으며 PILOT-9에서 구현한다.
실물 로봇의 위치 재조정이나 별도 안전 센서 연동은 이번 구현에 포함하지 않는다.

이력·감사·이벤트 관리 메뉴, 인증된 운영자와 영구 이력의 보존·조회 범위는
**PILOT-18로 이관**했다. [후속 기획 문서](../../concept/backlog/history-audit-events.md)를 참고한다.
