# 로봇 상태와 점유 복구 정책

## 상태를 분리하는 이유

운영 권한은 FMS 정책이며 물리 동작은 로봇 보고다.

| 축 | 값 |
| --- | --- |
| workState | idle / busy / unknown |
| fmsControlState | enabled / disabled |
| connectionState | online / offline |
| driveState | stationary / moving / waiting / paused / blocked / unknown |

미종료 작업은 점유 대기 중에도 busy다. moving은 이동·회전 관측을 뜻하며 허가만으로 정하지 않는다.
통신 두절 시 작업·주행은 unknown으로 투영하고 마지막 위치와 보고 시각을 남긴다.
disabled + online + moving도 표현할 수 있어야 한다. 통신 재접속만으로 enabled가 되지 않는다.
원인 목록은 driveContextJson에 source, 리소스 참조, 차단 로봇, 요청 ID, 허가 상태, 시작 시각을 담는다.

## 영속 점유

semantic corridor/complex/release 존의 occupied, reserved, queued 상태와 FIFO 순서를 DB에 보존한다.
오프라인·제어 동기화 전 보유자는 실제로 비웠다는 확인이나 명시적 복구 전까지 유지한다.
대기열도 보존하되 연결·동기화가 확인된 로봇만 허가한다.
legacy 동적 corridor lease의 단기 허가를 영구 점유로 복원하지 않는다.

## 사용자와 확정한 복구 규칙

1. 사용자가 구역과 로봇의 점유를 선택하고 해제를 확인한다.
2. 선택한 점유 해제, 해당 로봇 disabled, controlEpoch 증가, 감사 기록을 같은 DB 트랜잭션에 저장한다.
3. 과거 허가·경로를 무효화하며 선택하지 않은 다른 점유는 유지한다.
4. 늦은 보고나 재접속으로 운영 참여·해제된 점유가 되살아나지 않게 한다.
5. 운영 제외 중에도 텔레메트리와 UI 관측은 유지한다. 정상 명령·트래픽 참여는 차단한다.
6. 운영 제외 중에는 `move`·`dock` 등 운용 명령을 거부한다. 연결된 가상 로봇에 한해
   `테스트 위치 지정`만 허용하며, 이 동작도 운영 재개를 자동으로 수행하지 않는다.

위 선택 해제는 개별 리소스의 복구 동작이다. 로봇 단위 **운영 제외** 버튼은 아래 전체 복구 정책을 적용한다.
운영 제외·오프라인 로봇의 과거 이동 경로는 제거하지만 마지막 물리 위치는 다른 로봇의 장애물로 유지한다.
DB 처리 성공은 실제 로봇의 정지·이동 확인과 별개다.

2026-09-22 추가된 [사용자 일시정지·재개](../../concept/current/operator-motion-pause.md)는
위 운영 제외와 별도다. 명령·경로·점유·세대를 보존하며 저장된 정지 의도는 운영 제외와
명시적 재활성화에도 유지한다. 적용 ACK 확인 전에는 성공으로 표시하지 않는다.

## 운영 제외 시 전체 강제 해제

센싱·제어 오류나 물리적 문제로 FMS의 논리 상태와 실제 상태가 어긋날 수 있으므로,
사용자가 명시적으로 운영 제외하면 해당 로봇의 모든 논리 점유·예약·대기열을 해제한다.
텔레포터 이용권과 대기열도 포함하며, 진행 중 전환은 실패 처리한다. 다른 로봇의 기록은 보존한다.

제어 세대를 갱신하고 과거 명령·경로·이전 상태를 무효화한다. 로봇은 위치·상태 보고를 계속하지만
오래된 보고나 재접속으로 해제된 예약 또는 이전 작업을 자동 복원하지 않는다.
재시작 후에도 운영 제외가 유지되며 사용자가 운영 재개를 요청해야 한다.

두 맵은 공통 운영 제외 기록의 제어 세대를 적용한다. 로컬 DB와 공유 DB 사이에 중단된 처리는
미완료 복구 기록으로 재처리한다. 재처리는 새 세대를 반복 생성하지 않으며, 이미 명시적으로
재개한 뒤의 오래된 제외 기록은 다시 적용하지 않는다. 이전 맵에 남은 논리 점유도 정리한다.

논리 점유 해제는 공간이 비었다는 확인이 아니다. 관측된 로봇 몸체는 충돌 회피 대상으로 남는다.
단순 통신 단절은 운영자의 명시적 강제 해제와 다르며 기존 점유 보존 정책을 유지한다.

기존 내부 복구 기록은 유지한다. 인증된 운영자, 영구 명령 이력과 통합 이력·감사·이벤트 관리 메뉴는
[PILOT-18 후속 기획](../../concept/backlog/history-audit-events.md)으로 분리했다.

## 명시적 재활성화

연결과 최근 3초 이내 보고를 확인한 후 새 제어 세대로 동기화를 시작한다.
처리 중 DB 상태는 disabled다. 같은 sessionId/controlEpoch의 최신 pose 다음 control_ack가 도착해야 한다.
서버는 idle, stationary와 유효 위치를 확인한 뒤 enabled를 저장한다.
실패·timeout·연결 교체 시 disabled를 유지하고 세대를 올려 늦은 ACK를 무효화한다.
과거 작업은 자동 재개하지 않는다.

요청에는 requestId와 현재 controlEpoch가 필요하다. 오래된 화면의 요청은 거부한다.
같은 클라이언트 세션에서 최근 완료된 동일 요청은 응답을 재사용한다.
감사 처리자는 현재 Colyseus 세션 ID이며 인증된 사용자 계정은 아직 없다.
